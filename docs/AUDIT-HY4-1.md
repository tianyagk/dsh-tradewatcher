## 2. 渲染层无 0：证伪（一处；其余干净）

- 曲线：某市场日线失败 ⇒ 该序列在曲线里整段 `null`（`null=179/180、0=0`），先线断开而非画 0。
- 饼图：缺的市场不进 slices，并在饼图下方说明。

**证伪的一处**（`probe10.ts` 场景 a：五个上游全部失败 + 无快照）：

```
  整表 0 顶替: 通过
  脚注=["份额合计 = 0.00%（分母只含这一天有值的 0 个市场）","动量列 = 20 / 60 / 120 日收益率（…）"]
```

`份额合计 = 0.00%` 是**对一次「什么都没取到」的合计值显示 0**：
- 来源：`src/client/tools/globalFlowView.ts:221` —— `fmtSharePct(shownShares.reduce((sum, v) => sum + (v ?? 0), 0))`，把「没有值」按 0 参与求和；
- 它显示在市场表区块的脚注里，与「未取到」的期望不符（红线 1：缺数据必须显示「未取到」+ 原因，不得用 0 顶替）。

**并且锁它的断言是恒真的**（`src/host/globalFlow.test.ts:577`）：

```
const footnote = '份额合计 = 0.00%（分母只含这一天有值的 0 个市场）';
/^0(\.0+)?/.test(footnote)   // ⇒ false（脚注以「份额合计 = 」开头，^0 永远匹配不到）
```

即：这条"脚注也不许出现 0"的断言对 `0.00%` **视而不见**。

**判定**：命题 2 证伪（一处，且断言未看守）；表/饼图/曲线/KPI 四处干净。

## 6. 并发与缓存：主体证实（含 2 条附带缺陷）

**探针**：`probe2.ts` 命题 6（自造 14 请求清单）：

```
  冷启动=14 次：hq.sinajs.cn/list=fx_susdcny, gb_spy, 新浪美股日线 spy, 腾讯 us.INX, gb_vgk, vgk, gb_ewj, ewj,
               新浪 ETF 节点 getHQNodeData, 腾讯 sh510300, 腾讯 sh000300, gb_eem, eem, MoneyFlow sh510300
  TTL 内热取 ⇒ +0
  并发 2 次冷启动 ⇒ 14 次（基线 14）✅ 只打一遍
  source=snapshot ⇒ +0 次上游；曲线=1；replay=1
  换帧 4 次 ⇒ +0 次
  路由 ?source=snapshot ⇒ +0 次；source=snapshot
  路由 ?source=whatever ⇒ HTTP 400（应 400）
  路由默认 ⇒ HTTP 200；source=live；+14 次
```

**附带缺陷 A：失败会进缓存（与报告 §4 的「失败不进缓存」不符）**。`probe11.ts`：

```
━━━ ① marketRaws：fx 失败后恢复，30 分钟内是否重打上游
  失败轮：fx.value=null；fx 请求数=1
  恢复轮（同一进程内，30 分钟 TTL 未过）：fx 请求数=0；fx.value=null
  ⇒ 失败值被缓存（30 分钟内不会重试）
━━━ ② marketRaws：gb_ 网络失败（抛错）是否进缓存
  恢复轮：gb 请求数=4；美股 aumNative=822272781554   ⇒ 抛错路径未进缓存（会重试）✓
━━━ ③ 资金流：用未来 now 越过载荷 TTL，看 MoneyFlow 是否重打
  重建轮（+3 分钟，上游已恢复）：上游总请求=0；MoneyFlow=0 次   ⇒ 失败被缓存（不会重试）
```

原因：`globalFlow.ts:599-606`（fx）与 `:822-829`（资金流）把上游失败 **catch 在 loader 内部** 并正常返回 `null` / `[]`，
于是 `cached()` 把它当成功值写进 30 分钟 TTL 的槽位；`gb_*` 那条是抛出路径，行为与文档一致。
影响：一次瞬时抖动会让 A股 在最多 30 分钟内持续缺席美元分母（载荷 2 分钟的"残缺 TTL"救不回来），资金流栏同理。

**附带缺陷 B：回退态状态行误报 provenance**。`probe10.ts` 场景 b（先成功落 1 天快照，再让全部上游失败）：

```
  source=snapshot fallbackDay="2026-10-12"
  状态行 = 数据时刻 2026-10-12 21:00（北京时间）｜本次只读本地快照（不发上游请求）；快照已累积 1 天｜曲线 1 个序列日（实测 1 / 重建 0）
  missing[0] = {"what":"实时取数","why":"transient","note":"五个市场的上游本次全部失败 ⇒ 下表与曲线来自最近一次本地快照（不是实时值）"}
```

界面说的是「本次只读本地快照（**不发上游请求**）」，但本次实际发了 14 次上游、全部失败。
`globalFlowView.ts:165-169` 先判 `source === 'snapshot'`，而回退载荷的 `source` 也是 `'snapshot'` ⇒ 专为回退写的那句
「上游本次全部失败 ⇒ 下面是最近一次本地快照（…）」是**不可达的死分支**（`buildLivePayload` 的 live 载荷 `fallbackDay` 恒为 `null`）。
另：无快照的全缺场景里，同一条 `missing[0]` 文案仍说「下表与曲线来自最近一次本地快照（不是实时值）」—— 此时根本不存在快照。

**判定**：命题 6 主体证实（并发合并、零上游、400 都对）；两条附带缺陷属「口径诚实 / 文档与实现不符」。

## 7. 断言强度抽查（反向注入）：部分证伪

注入方式：真改 `src/` 源码 → 跑真测试 → `git checkout` 还原 → `sha256sum -c`（还原前/后见下）。
基线 sha256：`1260a354…`（globalFlow.ts）、`408b5129…`（globalFlowView.ts）。

| # | 注入（关掉什么） | 文件 | 测试结果 | 判定 |
| --- | --- | --- | --- | --- |
| ① | 分母把缺值当 0 参与求和 | `globalFlow.ts` `sharesOf` | `pass 14 / fail 0`，EXIT=0 | **无效注入**：加 0 不改合计，算术等价，不算反例 |
| ② | 缺值市场的份额返回 `0`（而不是 `null`） | `globalFlow.ts` `sharesOf` | `fail 2`，EXIT=1 | **抓到**：`①「缺值的市场不进分子也不进分母」`、`②「份额也必须 null」` |
| ③ | `fmtUsd(null)` 返回 `'0.00 亿美元'` | `globalFlowView.ts` `fmtUsd` | `fail 4`，EXIT=1 | **抓到**：格式化测试 + 缺市场行 + 整表无 0 检查（DOM 层同步能抓） |
| ④ | **实测日缺的市场用重建值补洞** | `globalFlow.ts` `buildCurve` | `pass 14 / fail 0`，EXIT=0 | **没抓到**（见下） |

注入②③的首条失败断言（原文）：

```
AssertionError [ERR_ASSERTION]: 缺值的市场不进分子也不进分母
AssertionError [ERR_ASSERTION]: 份额也必须 null   →  0 !== null
AssertionError [ERR_ASSERTION]: 没有值就是「未取到」  →  '0.00 亿美元' !== '未取到'
AssertionError [ERR_ASSERTION]: 欧股行必须是「未取到」：[…"0.00 亿美元",…]
```

**注入④ 的判别实验**（`probe5.ts`：手工造一份 10-08 的快照，那天欧股缺；本轮欧股有值 ⇒ anchor 存在）：

```
  原版：2026-10-08(origin=observed) 欧股 share=null          → 真洞（正确）
  注入：2026-10-08(origin=observed) 欧股 share=0.03170538409545358 → 被重建值补洞（红线违规，注入生效）
  注入态下跑交付方全量 host 测试：tests 14 / pass 14 / fail 0，EXIT=0
```

即：**代码注释与报告承诺的「实测日的洞必须是真的洞（不拿重建值去补）」在行为上可被静默破坏，而 14 条 host 断言一条都不报警**。
