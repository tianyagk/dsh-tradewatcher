## 1. 名词、符号与数据层

### 1.1 符号表（公式里只用这些）

| 符号 | 含义 | 单位/口径 |
|---|---|---|
| `C_t` | 第 t 根**已完成**日K收盘 | 元，fq=1 |
| `O_t / H_t / L_t` | 第 t 根开/高/低 | 元，fq=1 |
| `V_t` | 第 t 根成交量 | **手**（1 手 = 100 股/份） |
| `A_t` | 第 t 根成交额 | 元（日K缓存**不存**，见 §1.3） |
| `P` | 实时现价（`quote.price`） | 元，原始价 |
| `p0` | 昨收（`quote.prev`） | 元 |
| `t` | 窗口末端下标（最后一根 final bar） | 索引，非日期 |
| `n` | 窗口长度（交易日根数） | 根 |
| `asOf` | 本次因子计算的时刻 | epoch ms |
| `D_final` | 最后一根**已完成** bar 的 `barDate` | `YYYY-MM-DD` |
| `ρ` | 参与率（`settings.participationRate`，默认 0.10） | 分数 |

> **"已完成"的唯一判据**：`bar.date < today` **或**（`bar.date == today` 且当前 ≥15:05 且该 bar 来自收盘后的回源）。
> 盘中由实时快照补出来的那根（`liveTodayBarOf`）**永远**不算已完成。

| 数据 | 位置 | 时效 | 口径 | 可用字段 | 本表用法 |
|---|---|---|---|---|---|

### 1.3 三条数据层的硬事实（写公式时不能忘）

1. **日K没有成交额**。`DayBar` 只有 `vol`（手）。所以 `ADV20` 必须用 `V×100×C` 还原，并在信封里标 `method:'vol×close×100'`；
   缓存里若有 `unitNote`（≈100× 量纲断层已归一）必须原样带出，否则 `ADV20` 会差 100 倍。
2. **`pct` 字段可能是 `null`**（上游没给），涨跌幅一律用 `close` 自算，不读 `pct`。
3. **`fetchKline` 返回最近 N 根**，N 由调用方给（`KLINE_FULL_LMT[101]=800` 只是首次回填量；缓存增量追加，实测单文件 **834** 根）。
   任何"历史某天"的因子都必须先按 `barDate ≤ asOf` 过滤 —— 见 §5.4。

### 1.4 三类资产的差异（决定因子能不能算）

| 维度 | 股票 | ETF | 指数 |
|---|---|---|---|
| 复权 | fq=1（前复权） | fq=1 | **fq 恒 0**，`fqSupported=false` |
| 最小变动 | 0.01 元 | 0.001 元（债/黄金/跨境同） | 无（不可交易） |
| 涨跌幅限制 | 主板 10%；创业板/科创板 20%；北交所 30%；ST 主板 5% | 10% | 无 |
| 交割 | T+1 | 股票ETF **T+1**；债券/黄金/跨境/货币/商品 ETF **T+0** | — |
| 印花税 | 卖出 0.1% | **免** | — |
| 最低申报 | 100 股（科创板 200 股起） | 100 份 | — |
| 执行类因子 | 全可算 | 全可算 | **`TICK/FILL/LIMITDIST` 恒 `null`** + 原因「指数不可交易」 |
| 特有风险 | ST/退市/停牌 | 折溢价、T+0 滥用 | 只能做环境变量，不能选股 |

> **规则**：指数永远不进「可下单候选」，它的因子只用于**择时环境**（当期只读，不进下单候选，也不入候选池文本）。
> 表里凡是执行类因子，遇到指数一律 `v=null` + `missing="指数不可交易"`，**不要**用 0 或全市场均值顶替。

## 2. 因子总表

### 2.1 核心因子（12，必选）

> 单位约定：`%` 已在公式里 ×100；`0–100` 是分位；`ratio` 是 0–1 分数；`元`、`min` 如字面。
> 「更新」列：`日频` = 每个交易日 15:05 定稿后重算一次；`盘中10s` = 跟行情槽同频；`盘中60s` = 与做T扫描同频。

| ID | 名称 | 公式（窗口 / 分母 / 复权） | 单位 | 适用 | 来源 | 更新 | 缺失处理 |
|---|---|---|---|---|---|---|---|
| `TRD.MOM20` | 20日动量 | `(C_t / C_{t−20} − 1) × 100`；窗口 20 个交易日；分母 `C_{t−20}`；**fq=1** | % | 股/ETF/指数 | 日K | 日频 | `bars<21` ⇒ `null`，原因「日K不足21根」 |
| `TRD.MA20DEV` | 对 MA20 偏离 | `(P / MA20_t − 1) × 100`；`MA20_t = (1/20)ΣC_{i}`；窗口 20 根**final**；分母 `MA20_t`；fq=1（P 与 fq=1 末根同量纲） | % | 股/ETF/指数 | 日K + 行情 | 盘中10s | `bars<20` 或 `P=null` ⇒ `null`，原因分别写 |
| `POS.PCT252` | 52周区间位置 | `(P − Lmin) / (Hmax − Lmin) × 100`；窗口 **365 自然日**（约 245 根）；`Hmax=max(H_i)`、`Lmin=min(L_i)`；fq=1 | 0–100 | 股/ETF | 日K + 行情 | 盘中60s | 窗口内 `<2` 根 ⇒ `null`；美股 ⇒ `null` + 「仅原始价，拆股失真」（`positionRefusal` 既有口径） |

| `TRD.EFF20` | 趋势效率 | `|C_t − C_{t−20}| / Σ_{i=t−19..t} |C_i − C_{i−1}|`；分母是 20 段**路径长度**；fq=1 | ratio 0–1 | 股/ETF/指数 | 日K | 日频 | 路径为 0 ⇒ `null`；`<21` 根 ⇒ `null` |
| `LIQ.ADV20` | 20日日均成交额 | `(1/20) Σ_{i=t−19..t} V_i × 100 × C_i`（V 单位手）；fq=1 | 元 | 股/ETF | 日K | 日频 | 有效量 `<15` 根 ⇒ `null`；指数 ⇒ `null` +「指数无成交额口径」 |
| `EXE.TICK` | 最小变动占比 | `tickSize / P × 100`；`tickSize` 由**资产类别表**给（股票 0.01 / ETF 0.001），不由价格猜 | % | 股/ETF | 类别表 + 行情 | 盘中10s | `P=null` ⇒ `null` |

### 2.3 `AMP20` 与 `RANGE20` 必须分开（口径变更，**不兼容**）

现网 `amp20` 实际算的是 **20 日区间幅度**：`(max H_{20} − min L_{20}) / C_t`。
本机实测中位数 **27.92%**，而同一批标的的**日均振幅**中位数只有 **4.54%** —— 差 6.1 倍。
两者经济含义完全不同：

| 口径 | 回答的问题 | 中位（实测） | 用途 |
|---|---|---|---|
| `VOL.AMP20`（日均） | "平常一天能走多宽" | 4.54% | 做T档距、成本覆盖 |
| `VOL.RANGE20`（区间） | "20 天累计走了多大箱体" | 27.92% | 突破/箱体位置 |

**处置**：
1. 旧字段 `20日振幅` 在提示词与回包中**必须改名**为 `20日区间幅度`，或直接换成 `VOL.AMP20`；
2. 两者都保留时，**禁止**共用"振幅"二字（这是 `docs/AUDIT-PRISM-B2.md` 里"看着正常的错数"的同一类）；
3. 旧门槛 `20日振幅 ≥ 3%` **废止**（对 `RANGE20` 无意义，对 `AMP20` 也几乎不筛）。

## 3. 核心因子的经济含义与用途

### 3.1 逐因子说明（含义 / 10分钟决策用途 / 明确不能做什么）

| ID | 经济含义 | 用途（选股/择时/做T/风控） | **不能用来做什么** |
|---|---|---|---|
| `TRD.MOM20` | 过去一个月的中期方向。它度量**已实现**的价格位移，不含任何未来信息 | **选股**：同池横向比较"谁在走强"；**风控**：与成本同向时决定是否减仓 | 不能预测未来 10 分钟或 20 日收益；不能单独作为买入理由（动量在 A 股 10 分钟尺度上无稳定 edge） |
| `TRD.MA20DEV` | 现价相对 20 日均价的偏离，即"短期贵/便宜" | **择时**：偏离 > +2×ATR% 视为过热、< −2×ATR% 视为超跌；**做T**：正T 只在负偏离时考虑买腿 | 不能当估值；不能当支撑位（均线不是价格地板） |
| `POS.PCT252` | 现价在一年区间里的相对位置（0=年内最低，100=最高） | **风控**：接近低点(<10)且持仓浮亏 ⇒ 触发复核；**做T**：极高位反向T更易被套 | **不是"便宜"**、**不是"该买"**、不含基本面；低位可以更低（`position.ts` 原话：只描述相对自身位置） |
| `VOL.ATR14` | 日均真实波幅占价格的比例 —— 一天"正常能走多远" | **做T**：档距来源 `s=ATR/4`；**风控**：止损宽度不应小于 1×ATR | 波动 ≠ 收益；高 ATR 只说明**振幅大**，不说明方向；不能用于收益预测 |
| `VOL.AMP20` | 过去 20 天平均日内高低差（相对昨收） | **做T**：判断"日内有没有肉"，与 `ATR14` 交叉验证；**执行**：成本覆盖测算 | 同上；且是**历史**振幅，今天可能完全不波动 |
| `VOL.ATRRANK120` | 当前波动在**自身**近 120 日中的分位 | **择时**：识别"波动收缩/扩张"状态；**做T**：只在 ≥40 分位时开网格（自适应核心） | **不能跨标的比较**（分位是自比的）；不能推出"要涨/要跌" |
| `TRD.EFF20` | 20 日净位移 / 路径长度（Kaufman 效率）：1=单边直线，0=原地震荡 | **做T**：≤0.45 才做（震荡市）；**择时**：>0.7 视为强趋势，禁止逆势做T | 高效率 ≠ 会延续；它只描述**过去**走得直不直 |
| `LIQ.ADV20` | 20 日日均成交额 —— 市场每天能给多少流动性 | **执行**：算 `FILL`、判"这笔单会不会砸出坑"；**风控**：单票持仓 ≤ k×ADV20 | 流动性好 ≠ 会涨；它只降低冲击成本 |
| `EXE.TICK` | 一个最小变动价位占价格的比例 —— "一跳有多贵" | **执行**：`TICK > 0.10%` 直接判不适合做T（9 元股一跳 0.108%，往返滑点 0.216%） | 与收益无关；它是**摩擦成本**，不是信号 |
| `EXE.FILL` | 按当前参与率，把这笔单填完需要多少分钟 | **执行**：`>3 min` 说明这笔相对成交额太大，需拆单或缩小规模 | 与方向无关 |
| `EXE.LIMITDIST` | 现价距最近涨/跌停还有多少空间 | **风控/执行**：不足 1.5×ATR 时两腿都可能封死；**禁止**在距板 <1% 的标的上做T | 不能用来"博涨停"；距离近只说明**风险**高 |
| `PRT.WEIGHT` | 该标的占总资产的比例 | **风控**：对上 `perStockPct`（默认 30%）、`industryLimits`；**做T**：单轮 ≤ min(可卖, 20%×qty) | 不是"看好程度"；权重高只说明暴露大 |

### 3.2 **明确不能用于收益预测的因子（写进契约，不许模型自行发挥）**

以下 9 类在本系统里是**状态描述量**，任何"因为它高/低所以会涨"的推理都属越界：

1. **全部执行类**：`EXE.TICK`、`EXE.FILL`、`EXE.LIMITDIST`、`EXE.FEE_RT`、`EXE.T0` —— 只回答"做不做得成、划不划算"。
2. **全部位置类**：`POS.PCT252`、`POS.PCT20` —— 相对位置不是估值，也不是均值回归承诺。
3. **全部波动类**：`VOL.ATR14`、`VOL.AMP20`、`VOL.ATRRANK120`、`VOL.RANGE20` —— 波动是**做T的原料**，不是方向的预测器。
4. **全部流动性类**：`LIQ.ADV20`、`LIQ.VOLRATIO`、`LIQ.AMIHUD`、`LIQ.TURNOVER` —— 只影响成本与容量。
5. **全部组合暴露类**：`PRT.WEIGHT`、`PRT.INDW`、`PRT.CASH` —— 风险约束，不含 alpha。
6. **分档/分位类**（`groupRank` 的 极冷/中性/极热）—— 描述"同组内相对位置"，`groupRank.ts` 已明示"不是买卖建议"。
7. **`TRD.EFF20`** —— 过去走得直不直，不等于会继续直。
8. **PE/PB/总市值** —— 估值状态，不是 10 分钟信号（本表只保留为参考字段，不参与任何判定）。
9. **任何由上述因子线性组合出来的"综合分"** —— 见 §6，**禁止构造**。

> 唯一允许的"预测性"表述是**条件概率式的风险陈述**，例如「距跌停 1.2% 且 ATR 3%，今日被封死的概率显著高于常态」——
> 这是**风险**陈述，不是**收益**陈述，且必须带条件与数据来源。

## 4. 做T专用因子

### 4.1 七个因子（口径固定）

| # | 因子 | 公式 | 单位 | 备注 |
|---|---|---|---|---|
| T1 | `VOL.ATRRANK120` | 见 §2.1 | 0–100 | **自适应核心**：绝对 ATR 高不等于"现在波动大" |
| T2 | `VOL.AMP20` | 见 §2.1 | % | 用**日均**，不用区间 |
| T3 | `TRD.EFF20` | 见 §2.1 | 0–1 | 越低越适合做T |
| T4 | `EXE.TICK` | 见 §2.1 | % | 一跳占价格比 |
| T5 | `LIQ.ADV20` + `EXE.FILL` | 见 §2.1 | 元 / min | `N` = 单轮名义额 |
| T6 | `EXE.LIMITDIST` | 见 §2.1 | % | 取上下两方向**较小**者 |
| T7 | `INT.VWAPDEV` | `(P − VWAP_t)/VWAP_t × 100`；`VWAP_t = ΣA / (ΣV×100)`，当日 09:30 起累计 | % | 缺 `amount` 时用典型价近似，标 `avgApprox=true` |

**T7 的三个必带质量位**（缺一不可，否则不做判据）：
- `vwapFrom`：分时第一点时刻（若晚于 09:31，VWAP 有偏，须标注）；
- `vwapApprox`：是否用 `(H+L+C)/3` 近似（真值 vs 近似，二者不可混比）；
- `vwapSamples`：参与累计的分钟点数（<30 点不判）。

### 4.2 门槛链（顺序固定，**全部可复算**）

单轮名义额 `N` 与轮次股数 `R` 先算：

```
R = min( floor(available / 100) × 100 ,            // T+1 可卖（T+0 品种此项不限）
         floor(qty × 0.20 / 100) × 100 ,           // 单轮 ≤ 底仓 20%
         perOrderYuan ? floor(perOrderYuan / P / 100) × 100 : ∞ )   // 设置里的单笔上限（可空）
N = R × P
若 R < 100 或 N < 5000 ⇒ skip('fee-gate')          // 与主决策费用门槛同一口径（prismRoutes.ts:714）
s = ATR14% / 4                                     // 档距（沿用 tWindow 定稿）
feeRT% = (feesOf(buy,P,R) + feesOf(sell,P,R)) / N × 100
```

> `N ≥ 5000` 是**下限**不是上限：低于它时最低佣金 5 元/腿会把费率推到 0.2% 以上，
> 与 `applyFeeGate` 的判据一致。所以小单不是"缩小做"，而是"不做"。

| 闸 | 条件 | 建议阈值 | 自适应公式 | 不通过时的 `skipCode` |
|---|---|---|---|---|
| G0 | 行情可用 | `stale.level == 'fresh'`（≤15s，且 `source != 'lkg'`） | — | `stale-quote` |
| G1 | 可交易 | 非停牌、非一字板、`R ≥ 100`、正T 需 `cash ≥ N+fee` | — | `not-tradable` |
| G2 | 波动绝对下限 | `ATR14 ≥ 1.0%` | `max(1.0, 2 × (feeRT% + 2×TICK))` | `atr-floor` |
| G3 | 波动相对分位 | `ATRRANK120 ≥ 40` | 池内样本 ≥8 时另要求池内分位 ≥30 | `atr-rank` |
| G4 | 日均振幅 | `AMP20 ≥ 1.2%` | `max(1.2, 0.6 × ATR14)` | `amp-floor` |
| G5 | 趋势效率 | `EFF20 ≤ 0.45` | 高波动票（ATR≥5%）放宽到 0.55 | `trend-too-strong` |
| G6 | 一跳成本 | `TICK ≤ 0.10%` | `≤ 0.5 × s` | `tick-too-coarse` |
| G7 | 流动性 | `FILL ≤ 3 min` | 高波动票 ≤1 min | `too-illiquid` |
| G8 | 涨跌停余量 | `LIMITDIST ≥ max(1.0, 1.5 × ATR14)` | — | `near-limit` |
| G9 | 扣费净额 | `netEdge ≥ 0.25%`，且 `minSpread ≥ 0.8%` | 见下 | `no-economic-edge` |
| G10 | 当日计划数 | `rounds(secid, day) < maxRoundsPerDay`（默认 1） | — | `round-limit` |

**G9 的两个公式（本表新增，替换固定 1.2%）**：

```
netEdge%  = 2 × s − feeRT% − 2 × TICK          // 2s = 买在均价−s、卖在均价+s 的毛捕获
minSpread% = max( 0.8,
                  2.2 × feeRT% + TICK,          // 覆盖费用 + 一跳，留 120% 余量
                  0.25 × ATR14 )                // 至少吃到 1/4 个 ATR
```

> 为什么必须替换 1.2%：`feesOf` 的**最低佣金 5 元/腿**在小单上是毁灭性的。
> 100 股 @2.00 = 200 元，双边最低佣金 10 元 ⇒ `feeRT% = 5.1%`，1.2% 的价差毛赚 2.4 元、净亏约 7.8 元
> （与 `docs/AUDIT-AUTOT-HOST.md` #13 的算例一致）。公式法会自动把这类单判成 `no-economic-edge`。

### 4.3 触发与自适应（价位层）

```
买腿触发： P ≤ VWAP × (1 − 0.8 × s/100)      // 正T 开仓 / 反T 回补
卖腿触发： P ≥ VWAP × (1 + 0.8 × s/100)      // 正T 平仓 / 反T 开仓
失效：     P 突破 当日高点 × 1.01 或 跌破 当日低点 × 0.99 ⇒ 当日不做（invalidateIf）
强制：     14:50 未完成 ⇒ 按净差额回补（不是按计划股数，见 AUDIT-AUTOT-HOST P0#2）
```

**档距只由 `ATR14` 决定，不由当日振幅缩小**。现网 `tWindowView` 用 `min(ATR%/4, 当日振幅%/4)`，
在 09:35 当日振幅常常只有 0.3% ⇒ 档距被压到 0.075%，网格瞬间失效。
本表改为：`s = ATR14%/4` 固定；当日振幅只用于**开盘前判断要不要开网格**：

```
dayAmpProjected% = DAYAMP% × (240 / elapsedMinutes)     // 线性外推，仅用于"开不开"
开网格条件：dayAmpProjected% ≥ 2 × s
```

## 5. PIT / 前视处理规范

### 5.1 两个视图（本规范的地基）

| 视图 | 定义 | 允许进入的因子 | 绝不允许 |
|---|---|---|---|
| **`dailyFinal`** | `barDate < today` 的全部 bar；若已过 15:05 且当日 bar 为收盘后回源，则含当日 | 全部慢因子（`MOM/MA/ATR/AMP/RANK/EFF/ADV/PCT252`） | 盘中由快照补出来的那根（`liveTodayBarOf`） |
| **`intradayNow`** | 今日分时点 + 实时行情 + 当日累计 VWAP | 只允许替换**一个标量**：`P`；以及产生 `INT.VWAPDEV`、`VOL.DAYAMP` | 替换窗口内**任何一根**历史 bar |

**唯一合法的混用形态**：

```
MA20DEV = (P_now / mean(C_{t-19..t} [全部 final]) − 1) × 100
```

分子是盘中标量、分母是 final 窗口 —— 这是允许的；反过来（分子用 final 收盘、分母掺一根盘中 bar）**不允许**。

### 5.2 复权口径：一张决断表

| 用途 | fq | 理由 |
|---|---|---|
| 动量 / 均线 / ATR / 振幅 / 趋势效率 / 位置 / 区间 | **1**（前复权） | 不复权会把除权跳空读成暴跌，位置分位直接失真（`position.ts` 头注释的 NFLX 反面教材） |
| 现价 `P` / 成交价 | 原始价 | 前复权的锚在最新一根 ⇒ `fq=1` 末根与现价**同量纲**，可直接比 |
| 涨跌停价 `U/D` | **0** | 交易所按原始价算，用复权价会算错板 |
| 最小变动 / 最小申报 | **0** | 同上 |
| 成本对比（`avgCost`） | **0** | 账本记的是原始成交价 |
| 指数 / 期货 | **恒 0**，`fqSupported=false` | 无除权概念；`normalizeFq` 已强制 |
| 美股 | **0** | 上游只给原始价 ⇒ 位置类直接 `null` + 原因 |

**三条禁令**：
1. **禁止跨 fq 拼接**：一段序列里既有 fq=0 又有 fq=1 的 bar ⇒ 除权日会出现无解释跳空，`ATR` 与 `EFF` 全废；
2. **禁止用 `fqt` 请求值当口径**：必须读回包里的 `KlineData.fqt`（`normalizeFq` 会把指数收敛成 0）；
3. **同一行内的因子必须同口径**：`candidateStats` 现在 `fqt=0`（`prismRoutes.ts:358`）而 `ATR` 走 `fqt=1` —— 同一行里的 `close` 与 `ATR%` 来自两套价格，必须在统一前先修（见 §6.3）。

### 5.3 字段设计（`FactorEnvelope`）

```ts
/** 每个因子值的唯一输出形态。v 为 null 时 missing 必须非空；反之亦然。 */
export interface FactorEnvelope<T> {
  /** 因子值；缺失一律 null（**不许**用 0 / 50 / 均值顶替） */
  v: T | null
  unit: '%' | '元' | 'min' | 'ratio' | '0-100' | 'bool'
  /** 计算完成时刻（epoch ms） */
  asOf: number
  /** 窗口末端那根**已完成** bar 的日期；无日K时 null */
  dailyFinalAsOf: string | null
  /** 盘中标量的时刻（用了 P 才有；否则 null） */
  intradayAsOf: number | null
  /** 实际使用的复权口径（读回包，不读请求） */
  fq: 0 | 1
  window: {
    kind: 'tradingDays' | 'naturalDays' | 'intradayMinutes'
    n: number
    from: string | null      // 窗口起点（barDate / HH:mm）
    to: string | null        // 窗口终点
    samples: number          // 实际参与计算的样本数
    need: number             // 需要的最小样本数
  }
  stale: {
    is: boolean
    level: 'fresh' | 'delayed' | 'lkg' | 'stale'
    ageMs: number | null     // asOf − 数据时刻
    approxWorkdays: number | null  // 沿用 trendCaliber 的近似工作日口径
    reason: string | null
  }
  src: 'kline' | 'quote' | 'trend' | 'derived'
  quality: {
    partialBarExcluded: boolean   // 是否已剔除未完成 bar（必须 true）
    avgApprox?: boolean           // VWAP 是否用了典型价近似
    limitSource?: 'em-f47' | 'rule'
    unitNote?: string | null      // 量纲归一说明（ADV20 必带）
  }
  /** 非空 ⇒ v 必须为 null；一句话给人看 */
  missing: string | null
}
```

**四类 `stale` 的判定（写死，避免各处自造）**：

| level | 判据 | 允许用途 |
|---|---|---|
| `fresh` | 行情 ≤15s / 日K `dailyFinalAsOf` = 上一交易日 / 分时 ≤90s（盘中） | 全部用途，含下单 |
| `delayed` | 行情 15–60s；分时 90–300s | 只读展示；**禁止触发**做T |
| `lkg` | `source='lkg'`（本地兜底库 `quotes-lkg.json`） | 只读展示与估值；**硬拒单** |
| `stale` | 行情 >60s；日K 近似工作日 ≥2（沿用 `STALE_APPROX_WORKDAYS=2`） | 只读展示 + 显式提醒 |

**收盘后不误报**：`!inMarketWindow()` 时一律 `is=false`、`reason=null`，但回包保留 `sessionClosed=true`。
（`trendCaliber` 已用同一思路：陈旧只在需要新鲜的时候才叫陈旧。）

### 5.4 800 根与前视（本仓最危险的一处）

`fetchKline(secid, 101, lmt, fq)` 的内部是：

```ts
const want = Math.min(lmt, series.length)
const days = series.slice(series.length - want)   // ← 永远是"最近的"
```

所以：

| 场景 | 正确做法 | 错误做法（会前视） |
|---|---|---|
| 当前因子 | 直接取 `days` 末段 | — |
| 历史/回测某日 `asOf` | `bars.filter(b => b.date <= prevTradingDay(asOf))` 后再取窗口 | `bars.slice(-20)`（拿到的是**未来**的 20 根） |
| 定点复算 | 先算 `barDate` 索引，再 `slice(0, k+1)` | 用数组长度做锚 |

**可执行断言（实现后必须过）**：

```
A1. 取任意 k，令 asOf = bars[k].date（15:05）。
A2. 用 filter(barDate ≤ asOf) 算 MOM20，结果应等于 (bars[k].close / bars[k-20].close − 1) × 100。
A3. 同一实现若把过滤去掉（用全序列末尾），结果会不同；测试必须能捕获这个差异。
```

另一条硬约束：**窗口长度一律 ≤ 300 根**（52 周 = 245 交易日）。
超过 800 根的需求（如 3 年 ATR 分位）在本仓**不支持**，必须显式 `null` + 「历史窗口超过日K上限800根」，不许静默用 800 根近似成 3 年。

### 5.5 未完成 bar 的处理矩阵

| 因子 | 末根为未完成时 | 处理 |
|---|---|---|
| `ATR14` | 会低估（`H/L` 未走完） | **剔除末根**，用之前 15 根 final |
| `AMP20` | 会低估 | 剔除末根，用之前 21 根 final |
| `ATRRANK120` | 当前观测失真 | 剔除末根后再算分位 |
| `EFF20` / `MOM20` | 位移未完成 | 剔除末根 |
| `PCT252` | `P` 本身是盘中值 | **保留**（分子本来就该用现价），分母仍用 final 极值 |
| `MA20DEV` | 同上 | 保留（分子 `P` 盘中，分母 final） |
| `ADV20` | 当日量未走完 | 剔除末根（否则 ADV 被压低） |
| `VWAPDEV` | 本身就是盘中量 | 保留，但必须带 `vwapFrom` / `vwapSamples` |

实现侧只需一个判据：

```ts
const isFinal = (b: DayBar, klineBarOpen: boolean, i: number, n: number) =>
  !(klineBarOpen && i === n - 1)                  // 只有末根可能是未完成
```

### 5.6 LKG 硬拒单（把"标注"升级为"拦截"）

现状：`quotes-lkg.json` 兜底只写 `source='lkg'`，下单链路不校验。
本规范要求（设计层，实现另开）：

```
下单前：quote.source === 'lkg'            ⇒ reject('lkg-quote')
        quote.ageMs > 15_000              ⇒ reject('stale-quote')
        quote.price 与 上一次成交价偏离 >3%  ⇒ reject('price-jump')（既有偏离闸，保持）
```

因子层配套：`EXE.LIMITDIST` 与 `INT.VWAPDEV` 在 `lkg` 下**必须为 `null`**，不得用兜底价算出一个"看起来正常"的数。

## 6. 与 `candidateStats` 的边界

### 6.1 三条不做的事（红线）

| # | 不做 | 理由 |
|---|---|---|
| R1 | **不做综合评分**（不加权求和、不做 z-score 合成、不设"因子总分"） | 一旦有分数，排序就会自然发生，选股权就从人转移到公式；`candidateStats.ts` 头注释已写"不做选股评分" |
| R2 | **不做推荐榜**（不"Top 5 值得买"、不给目标价、不给买卖点） | 与 R12（引擎只提示、不自行发起交易）同一精神；推荐榜是最容易被误读为指令的形态 |
| R3 | **不做排序** | `candidatesTextOf` 明确"按输入顺序、未排序——排序本身就会变成隐性选股"，本表沿用 |

### 6.2 允许做的事

| 允许 | 形态 | 限制 |
|---|---|---|
| 同池分位 | `「ADV20 分位 82%」` | 必须写"同池相对位置"，并给池名与样本数 |
| 分档药丸 | 沿用 `groupRank` 的 `极冷/中性/极热` | 只在 UI 汇总行；不进模型正文 |
| 缺失标注 | `—` + 一句原因 | 原因必须可复算（"日K不足21根"，不是"数据异常"） |
| 因子原值 | `ATR14 4.43%（14日，前复权，截至 11-26）` | 必须带窗口/口径/截至日 |
