## ① 分布精度 ×3（32 → 96 桶）

- `CHIPS_BUCKETS` 32 → **96**；新增范围常量 `CHIPS_BUCKETS_MIN = 16`、`CHIPS_BUCKETS_MAX = 160` 与
  `normalizeBuckets()`：缺省 ⇒ 96（不报错不留痕）；越界 ⇒ **夹取**并留痕；非数字 ⇒ 回落 96 并留痕。
  路由参数 `buckets` 走同一个归一函数（保留可用）。
- **计算量（96 桶 × 360 根）**：逐日递推 = 每天「衰减 96 次乘 + 分摊 96 次加 + 归一化 96 次除」≈ **288 次/天 × 360 天 ≈ 10.4 万次浮点运算/标的**
  （纯内存、单帧内可忽略；对比：旧 32 桶时约 3.5 万次）。实测 `chipSeriesOf`（360 根 × 96 桶）在本机 **~19ms**（含 45 天状态记录）。
- **渲染行数**：96 行；行高由 `chipsRowHeight(可用高度, 96)` 给 = `max(1, floor(可用/96))` ⇒
  可用 192px ⇒ 2px/行；可用 96px ⇒ 1px/行；**不足 1px 也按 1px 画**（不静默丢桶、不出现 0 高度）。
- 断言：默认 96；`CHIPS_BUCKETS / 32 === 3`（不是顺手改个数）；越界夹到 16/160 且留痕；非数字回落；96 桶下**权重总和仍守恒**
  （为让守恒断言保持紧，桶权重存储精度从 6 位提到 **8 位** —— 96 桶 × 6 位舍入会让总和漂到 ~2e-6）。

## ② 左轴字体放大 + 横坐标刻度（占总筹码比例）+ 网格线

- 左轴价格刻度字体 **9.5px → 11px**（同字体族、不加粗）。
- **横坐标刻度**：`ratioTicks(peak)` 用 **nice step**（1/2/2.5/5 × 10^n，随峰值自适应）给出"该价位筹码占**总筹码**的比例"，
  标签形如 `0% / 0.5% / 1% …`；小数位由 `stepDecimals(step)` 决定 ⇒ **不出现 `0.30000000004`**；刻度数 3–6；峰值为 0 ⇒ 不出刻度。
- **网格线**：横轴刻度 ⇒ 竖线（`.tw-chips-grid-v`），纵轴价格刻度 ⇒ 横线（`.tw-chips-grid-h`）；两者都走
  `--tw-chips-grid` token（深浅两套都定义了值），**层级在横条之下**（先渲染网格、再渲染横条 ⇒ 网格不会盖住筹码条）。

## ③ 三条语义线（平均成本 / 压力 P95 / 支撑 P5）

- `chipsLinesOf()` 产出三条线的**坐标与标签**：坐标分别等于 `avgCost / resistance(P95) / support(P5)`，
  标签文本就是该数值（两位小数）；异常输入（任一缺失、非有限数、**P95 < P5**）⇒ 返回空数组（**不出线、不抛错**）。
- 渲染：横向**虚线**贯穿分布区（`.tw-chips-refline`，`border-top:1px dashed currentColor`），**右端数值标签**（`.tw-chips-reflabel`）。
- **配色合规（硬要求）**：三条是**语义线不是涨跌** ⇒ 只用新 token
  `--tw-chip-avg`（橙）/`--tw-chip-res`（紫）/`--tw-chip-sup`（蓝），**不用红/绿**、不碰 `dirClass/toneClass`；
  值在 `styles.ts` 的**深浅两套变量块**里都有定义，token 名集中在 `theme.ts` 的 `CHIPS_LINE_TOKENS`（源码里不出现硬编码色值）。
- **隐身档合规（容易漏的一条）**：新增的数值标签是**新的数字展示面** ⇒ 已登记进 `styles.ts` 的**两条** `data-blur=1` 清单：
  ```
  清单内容（两条一致）：.tw-chips-nums, .tw-chips-date, .tw-chips-bar, .tw-chips-reflabel, .tw-chips-xaxis
  为什么是这个数：筹码区的**数字面**共 5 类 —— 四个数字（nums）、日期（date）、分布条（bar，承载权重）、
  三条语义线标签（reflabel）、横轴比例刻度（xaxis）；后两类是本轮新增 ⇒ 旧断言（数到 bar 为止）同步更新，计数仍为 2 条清单 × 5 个选择器。
  ```
