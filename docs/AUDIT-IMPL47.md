## 3. 快照兼容（旧快照不得与新成分混用）

**数据结构**（`globalFlow.ts:530`/`:544`）：文件 `{ v: 2, scope, days, purged[], writtenAt }`；每天记录 `{ at, rates, scope, markets, momentum, ranks, totalUsd, rotationText, missing }`。

**两级校验**（`readFlowSnapshot`，`globalFlow.ts:579`）：

1. **文件级**：`v !== 2` 或 `scope !== FLOW_SCOPE` ⇒ 整份 `days` 不采用，逐条写进 `purged`（`reason` 里写清旧 scope 与新 scope 的差别）。
2. **逐日级**：文件头对、但某天记录的 `scope ≠ FLOW_SCOPE`（"同一文件里混了两种口径"）⇒ 只丢那一天，同样留痕。

**作废不删数据**：`purged` 只增不删，由下一次落盘写回文件（`writeFlowSnapshot`，`globalFlow.ts:627`）。
**留痕必须可见**：`flowSnapshotStats()` 带出 `purged`，载荷 → 视图 → 状态行（`globalFlowView.ts:258`），UI 会主动说"另有 N 天旧口径快照已作废"，否则用户只会看到"历史突然变短"。

**实测**（真网络隔离跑）：文件 `v = 2`、`scope = v2:cn,hk,us,jp,kr`、单日 ≈ 1632 B（90 天 ≈ 146 KB，一天一条） ✓
**迁移实测**（单测内）：手写一份 v0.72.0 形状的旧快照（含 `us/eu/jp/cn/em` 五个键）⇒ 载入后 `days = {}`、`purged` 1 条、旧日期不出现在曲线里；再写一份"v2 文件头 + 一条 v1 记录"的混合文件 ⇒ 只保留合规那天。
