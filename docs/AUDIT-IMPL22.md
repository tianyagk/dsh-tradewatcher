## 一、契约缺口（最值钱的一条）

**问题**：`guidanceText()`（`src/host/tools.ts`）里的工具一览是**手抄清单**，只列了 10 个；
v0.50.0 实际注册 **12 个** ⇒ `tradewatcher_position` 与 `tradewatcher_group_rank`
**对模型等于不存在**（注入段是模型唯一能看到的插件说明）。

**修法（从根上消除漂移，而不是补两个名字）**：
- 注入段的工具一览改为**由 `defs` 生成**（`toolLine()`）：`defs.map(...)` ⇒ 注册了哪些工具就列哪些，
  "新增工具却忘了写进注入段"在**结构上不可能发生**；
- 每个工具的一句短说明放 `TOOL_BLURB`（键 = 去前缀的工具名）；**说明可省、清单不可省**（没有说明时只列名字）；
- 12 个工具的一行说明就此补齐（`position`「位置类指标：52 周区间位置与距高低点」、
  `group_rank`「自选分组一屏排序（情绪/位置/涨跌幅）」等）。

**不变量断言（新增 `src/host/guidance.test.ts`）**：**注入段列出的工具集合 === 实际注册的工具集合**（双向包含）。
锚法（两边都取**真实实现**，刻意避免"写死清单对写死清单"的恒真陷阱）：
```
左侧 = 调 `registerTools()` 时宿主工具表**实际收到的** `def.name`（用假的 tools 收集器录下来）
右侧 = `prompt.section({ text })` **真实拿到的注入段正文**里出现的 `tradewatcher_*`（正则抓取，非拼接）
断言：missingInGuide === [] 且 extraInGuide === [] 且 两侧排序后 deepEqual；并额外断言"注入段至少提到 12 个"
（最后一条是防"一个都没写"造成的假通过）
```

**反例注入证据**（临时把 `position` 从注入段删掉 ⇒ 复现原 bug）：
```
✖ 注入段列出的工具集合 === 实际注册的工具集合（双向）
  AssertionError: 注入段漏列：tradewatcher_position        （恢复后 1/1 通过）
```

| 位置 | 现文 | 改为 | 理由 |
| --- | --- | --- | --- |

| `tools.ts` portfolio 描述 | …明细与**实时行情时间戳** | …明细与**数据时刻** | R1：同一概念只有一个写法（`asOf` = 数据时刻） |
