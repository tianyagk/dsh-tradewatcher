## 2. 因子冗余（六因子到底在数几件事）

**命题 2.1**：六个因子各自独立、无重复计权。
**方法**：从 `scoreLog[].factors[]` 取 302 个采样点的六因子**得分**，算两两 Spearman 相关；同时统计可用度与恒 0 情况。

```bash
python3 - <<'PY'   # §8.2
# 六因子×六因子 Spearman（n=302，只有同时有值的样本参与）
PY
```

**数字（n=302）**

| 因子对 | Spearman r | 读法 |
| --- | --- | --- |
| **persistence × superflow** | **+0.564** | ⚠ 高度相关：两者都在数"超大单在净流入" ⇒ 合计权重 0.12+0.26=**0.38** 有重复计权 |
| pulse × volume | +0.248 | 轻度重叠（脉冲是短窗量能） |
| persistence × volume | +0.208 | 轻度重叠 |
| divergence × pulse / volume / persistence | +0.153 / +0.118 / +0.102 | 基本独立 |
| superflow × volume | −0.029 | 独立 |
| **resonance × 任意** | 无法计算 | `resonance` 在 **302/302 个采样点恒为 0** ⇒ 权重 0.08 **从未生效** |

**因子可用度（"未取到"= `actual` 为 `—`）**

| 因子 | 未取到次数 | 备注 |
| --- | --- | --- |
| `persistence` 持续性 | **221 / 302（73%）** | 最常缺 |
| `pulse` 脉冲 | 35 / 302（12%） | |
| volume / superflow / divergence / resonance | 0 / 302 | `superflow` 虽不"缺"，但**测得的 0 分**出现在 **253/302（84%）** |

可用度 ⇒ `raw` 上限：缺 persistence ⇒ cap **88**（187 次）；缺 persistence+pulse ⇒ cap **70**（34 次）；全可用 ⇒ 100（80 次）。
再叠加 resonance 恒 0（0.08）⇒ 实际可达上限再降 8 分。

**判定：证实（存在重复计权与死权重）**。
① `persistence` 与 `superflow` 应合并或改为条件加分（避免同一件事拿 0.38 权重）；
② `resonance` 是**死因子**（恒 0，权重 0.08 白占 ⇒ 直接压低所有样本的可得上限）；
③ `divergence` 是**"今天跌了"的代理变量**：其得分对当日指数涨跌的斜率 = **−13.55 分/百分点**（即指数跌 1% ⇒ 该因子 +13.6 分），且 301/301 非零（均值 74.9）
⇒ 它更像市场状态的镜像，而不是"护盘"的证据。

## 3. 前视偏差（逐条核对时间戳）

**命题 3.1**：`forward` 与因子输入没有用到"当时还拿不到"的数据。
**方法**：逐个读输入构造代码，核对每个量的时间口径（`src/host/rescue.ts` 1430–1530、`src/host/signalForward.ts`、`src/host/tools.ts` 1338–1360）。

| 输入 | 时间口径（实测） | 结论 |
| --- | --- | --- |
| `avgAmt20`（20 日均额基准） | `bars.slice(-21, -1)` ⇒ **排除最后一根** | 无当日泄露 ✓（且失败时回落到 `RESCUE_CALIBRATION` 静态值） |
| `timeAdjMult`（量能倍数） | `amount / (base × progressCurve(elapsed))`，`amount` 是**当日到采样时刻的累计成交额** | 无前视 ✓ |
| `pulseMult`（脉冲） | 最近 5 分钟成交额 ÷ 同时点基准 5 分钟额（`pickPulseRef(minutes, evalTs)`） | 无前视 ✓ |
| `superVsAvg` / `superShare` | 到采样时刻的**累计**超大单净额 | 无前视 ✓ |
| `persistence` / `retraceRatio` | 采样环内的最近窗口 | 无前视 ✓ |
| `indexPct` / `resonance` | 采样时刻的指数与通道状态 | 无前视 ✓ |
| **`forward` 入场价** | **信号日收盘价**（`atOrAfter(bars, ev.day).close`）；信号本身是**盘中**触发的 | ⚠ **入场价 ≠ 信号时刻价** ⇒ 不是"信号后可得的收益" |
| **信号日的定义** | `history(30).filter(maxLevel ≥ 1)`，而 `maxLevel` 来自**当日全部采样**（含收盘后样本：实测 10-13 21:56 L1、10-09 22:26 L0、09-30 22:30 L0、10-12 16:49 L0） | ⚠ **潜在前视**：若某天只在收盘后才触发，则"信号日收盘价入场"是**用信号之前的价格入场** |
| 默认标的 = 基准 | `subject` 默认 `1.000300`，基准也是沪深300 ⇒ **超额恒 0**，`winRate` 显示 **0%** | ⚠ 数字误导（代码里有一句 note 兜底，但胜率/超额数字仍会照出） |

**判定**：**六因子输入无前视（证实清白）**；但 `forward` 有三处口径问题（**入场价、收盘后样本、默认标的=基准**）⇒ 判定：**证伪"forward 是信号后收益"这一说法**。
**需要什么**：入场改为"信号时刻之后第一根 5 分钟线 / 次一交易日开盘"，并把收盘后样本排除出日级最高等级；默认标的改 510300（或 `subject == bench` 时不显示胜率/超额）。

**附带证实一个更严重的问题**：**收盘后样本拿到最宽松的系数 1.1**（`elapsed > 180` 一直成立）⇒ 实测事件里有 21:56 / 22:26 / 22:30 / 16:49 这类采样，
即"夜里用最低门槛判等级"。这不是保守，而是**口径错误**：系数假设"越晚越接近尾盘"，收盘后该假设失效。
