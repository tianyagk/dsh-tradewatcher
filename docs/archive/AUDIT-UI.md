## 二、必修（信息错误 / 不可用）

### P0-1 云图配色与全局开关脱钩，且与第三方站点反向（S–M）
- 现状：`CloudMap.tsx:124` 向 `IndustryHeatmap` 传死值 `redUp: true`；色阶硬编码在 `IndustryHeatmap.tsx:21-28`（`229,72,77` / `39,166,68`）。其余页面都跟随 `prefs.redUp`：`TopBar.tsx:488`、`WatchlistPage.tsx:271/360`、`PortfolioPage.tsx:201/831`、`MarketPage.tsx:210/229`。
- 后果：设成"绿涨红跌"的用户在大盘页看到绿=涨，切到云图页看到**红=涨**；再切「第三方站点」（`CloudMap.tsx:157`，其官网口径为红跌绿涨）又反一次 —— 同一面板内三种口径并存，正是 `COMPETITOR-NOTES.md:51` 判为"要避免"的问题；该行还写着"自绘热力图也跟随它"，与代码不符。
- 改法：`CloudMap` 接收 `prefs.redUp` 并透传（调用点 `index.tsx:394` 需一并传参）；第三方分支加常驻提示「该站配色：绿=涨、红=跌，与本站相反」；`IndustryHeatmap.tsx:20` 注释"跟随主题"要么改成取 token、要么删掉。
- 验收：切入绿涨红跌后截图云图页，热力块涨色与 `MarketPage` 同一板块文字的涨色应为同一色。

### P0-2 市场宽度把"取不到"当 0 相加 / 显示（S）
- 现状：`MarketPage.tsx:116-119` 用 `(sh?.up ?? 0) + (sz?.up ?? 0)` 求 `upSum/downSum/evenSum/amountSum`；单元格 `MarketPage.tsx:235`、`351` 写 `String(q.down ?? 0)`、`String(r.down ?? 0)`；`IndustryHeatmap.tsx:114` tooltip 同样。
- 后果：只有沪市返回时，`上涨/下跌` 与 `上涨占比`（`MarketPage.tsx:180`）静默减半，看起来像"市场宽度收敛"；`up` 有值而 `down` 缺失时显示 `1234 / 0`，读作"没有一只下跌"。同文件 `MarketPage.tsx:167` 对成交额用了 `amountSum > 0 ? … : '—'`，两条路径标准不一致，也违反 `WatchlistPage.tsx:221` 明写的"不用 0 代替（0 会被读成没涨没跌，那是错的）"。
- 改法：四个合计先判各分量是否 `null`，任一缺失即整格 `—` 并把原因写进可见 hint / `title`；单元格把 `up`/`down` 合并判定。
- 验收：构造只有 `sh` 的数据快照，界面显示 `—` 而不是半个市场的家数。

### P0-3 Markdown 强调符泄漏到界面文案（6 处，S）
- 现状：`MarketPage.tsx:287`（"只在**本页 40 条**内重排"）、`PortfolioPage.tsx:1014`（"默认**不折算**"）、`RescuePanel.tsx:469/645/646`、`TopBar.tsx:373`（"只影响**本插件面板的显示**"）、`TopBar.tsx:399`。
- 后果：用户直接读到 `默认**不折算**`、`…**历史同类情形的频率**…`，会以为字符被截断或文件损坏 —— 而这些位置恰是"口径说明"，可信度直接受损。
- 改法：这 6 处是 JSX 字符串不是 Markdown，去掉 `**` 或拆成 `React.createElement('b', …)`；把 `grep -rn '\*\*' src/client/*.tsx` 加进自查清单，可一次抓出全部漏网。
- 验收：五个页面各截一图，文案中不出现 `*`。

### P0-4 输入控件失去可见焦点（S）
- 现状：`styles.ts:38` 对 `input,select` 设了 `outline:none`；`styles.ts:39` 想用 `box-shadow:var(--tw-focus)` 补焦点环，但 `--tw-focus` **全项目没有定义**（唯一出现处即该行；可用变量见 `styles.ts:11-35`，相近的 `--tw-ring` 在 `styles.ts:17/31`）。于是输入框只剩 1px 边框由 `#e2e5ea` 变 `#5e6ad2`；`TopBar.tsx:379-387` 的不透明度滑块内联写了 `border:none`，连这条边框也没有。
- 后果：Tab 到「数量/价格/费用/汇率」时几乎看不出焦点在哪；键盘调"面板不透明度"时**完全没有焦点提示**。行与卡片有 `:focus-visible`（`styles.ts:305`），K 线缩放滑块有完整 `role="slider"` + 方向键（`kline.tsx:715-748`），唯独表单控件这一环掉了 —— 标准不统一。
- 改法：`styles.ts:39` 改为 `box-shadow:0 0 0 3px var(--tw-ring)`；`range` 补 `:focus-visible{outline:2px solid var(--tw-accent);outline-offset:2px}`。
- 验收：纯键盘 Tab 过一遍持仓页弹窗，每一步都能看出焦点位置。

### P0-5 窄面板下行情条吞掉整屏，且无折叠入口（M）
- 现状：`styles.ts:59` 用 `repeat(auto-fill,minmax(112px,1fr))` + `gap:6px`；行情条共 3 组 23 张卡（`shared/model.ts:11-55`：cn 6 / intl 9 / commodity 8）；卡内容 3 行实测约 61px（`styles.ts:63` 的 `min-height:54px` 与 `.nm 11×1.4`、`.px 15×1.35`、`.chg 11×1.5`、`padding 4+5`，见 `styles.ts:159-162`）。
- 后果（按面板宽度代入）：宽 1600px 时每组 1 行、行情条共约 219px（可接受）；宽 360px 时每组一行只放 2 张（`floor((276+6)/118)=2`），三组 3+5+4=12 行 ≈ **780px**，再加页签 45px、面板头 ~48px、分组头 ~54px，第一行自选落在 y≈970px —— **800px 高的窗口首屏看不到任何自选/持仓数据**，而三组行情条没有任何折叠开关。
- 改法：`.tw-strip` 支持折叠（状态存 `prefs`，默认只展开"A股指数"）；或窄屏把卡片压到 `minmax(96px,1fr)` 并把 `min-height` 降到 44px（需同步简化 `.chg` 第二行）。
- 验收：窗口宽度 360px 时，第一行自选出现在首屏内。

### P0-6 窄面板下页签与筛选段控被裁且不可发现（S）
- 现状：`styles.ts:172-173` 给 `.tw-tabs` 设了 `overflow-x:auto` 且**隐藏滚动条**；单个 `.tw-tab` 最小宽 58px（`styles.ts:174`），5 个页签（`index.tsx:397-403`）含 padding/gap 约 334px。`styles.ts:286` 的 `.tw-seg` 是 `inline-flex` + `overflow:hidden`；日历页 7 个筛选按钮（`CalendarPage.tsx:186-192`）加重要度图例（`:195-198`）约 600px。
- 后果：面板 <340px 时「日历」页签被裁掉，且没有滚动条、没有渐隐提示，用户只会认为只有 4 个页签；日历页在窄面板下尾部类别（如"分红"）被直接裁掉且**无法滚动到**，等于该筛选项不存在。
- 改法：`.tw-tabs{flex-wrap:wrap}`（两行放得下）或保留可见滚动条 + 右缘渐隐；`.tw-seg` 改 `flex-wrap:wrap;overflow:visible`，窄屏可降级为 `select`。
- 验收：360px 宽面板下 5 个页签与 7 个筛选项全部可点。

### P0-7 新增的 YTD 数字面不在数字模糊白名单里（S，预防性）
- 现状：`styles.ts:130` 新增了 `.tw-ytd{font-family:var(--tw-mono);font-variant-numeric:tabular-nums}`，但 `data-blur=1` 的白名单（`styles.ts:136-150`，两处选择器列表）只收了 `.tw-wrow .tw-num`，**没有 `.tw-ytd`**；同一文件 `styles.ts:132-135` 的注释自己写着"新增数字展示面时必须同时加进这两条规则"。
- 后果：YTD 单元格若只挂 `.tw-ytd`（不额外挂 `.tw-num`），隐身视图的"数字模糊"会漏出真实 YTD 数字 —— 而隐身模式是给录屏/演示用的，漏一个面就等于没隐。
- 改法：把 `.tw-ytd` 加进 `styles.ts:136-150` 两条列表；或在 `WATCH_COLUMNS` 渲染时统一挂 `tw-num tw-ytd`（`sort.ts:78-85` 的列定义）。
- 验收：`Alt+M` 到隐身档 + 数字模糊，YTD 列必须一起糊住（截图比对）。

## 三、应修（效率与一致性）

### P1-1 排序键与可见列不对应（市值/成交额/α 挤在副标题）（M）
`sort.ts:78-85`（`WATCH_COLUMNS`）已把「成交额/市值/涨跌/涨跌幅/行业α」声明为**列**，但这些值在界面上只出现在行副标题里（`WatchlistPage.tsx:328-330` 市值、`:325` 成交额、`:335` 板块、`:343-350` α），副标题是 `flexWrap:'wrap'` 的自由流（`:323`）。后果：按总市值降序后每行换行位置不同、市值数字左右不对齐，**无法用"扫一列"核对排序结果**，只能逐行读；竞品该值是固定列。改法：自选行加固定宽度的右对齐数值列（市值、涨跌幅，α/行业移到第二行或详情），列宽与 `SortHeader` 的列顺序一一对应。验收：按市值降序截图，市值列落在同一条纵向网格线。`S/M`

### P1-2 列头排序正在落地：接入前必须解决三件事（M）
- 现状：`SortHeader.tsx` 已写好（真 `<button>`、`role="columnheader"` + `aria-sort`、带「↺ 默认顺序」回退），但**目前没有任何页面调用它**；同时 `styles.ts:127` 已写 `.tw-sortbar{display:none !important}`（说明见 `styles.ts:126`），即 ≥1500px 时段控被 CSS 强制隐藏。
- 后果与待办：① `.tw-sortbar` 被无条件隐藏，而替代品靠 JSX 渲染 —— 若某个页面漏挂 `SortHeader`，该页在 ≥1500px 下会**彻底失去排序入口**（连"默认顺序"都点不到）；② 行不是表格（`.tw-wrow` 是 flex 卡片行，`styles.ts:260-265`），列头按钮却按"列"排布 —— 点击目标与下方数字不对应，"点列头"的承诺落空，必须先做 P1-1 的列网格，否则应把 UI 措辞从"列头"降级为"排序键"；③ 窄屏（<1500px）下两者都不显示列头，而 1080–1500px 又没有多列（P1-9）。
- 改法：把"是否渲染 `SortHeader`"与"是否隐藏 `SortBar`"绑成同一条件（同一断点常量或同一 `prefs` 开关），不要一边 CSS 一边 JSX；接入顺序建议：先做列网格（P1-1）→ 再接列头。
- 验收：1500px 上下各截一图，两种状态下都至少存在一个可用的排序入口；宽屏点"市值"列头后，下方同列数字逐行对齐。

### P1-3 持仓页头部操作行在窄面板溢出（与自选页不一致）（S）
`WatchlistPage.tsx:146` 的面板头带 `flexWrap:'wrap'`，`PortfolioPage.tsx:209-248` 的同构行**没有 wrap**：标题 + 无价徽标 + 成本口径段控(2 键) + ⓘ + `SortBar` + 汇率 + 备份 + 刷新。排序键已从 5 个涨到 7 个（`sort.ts:27-34`），按钮按 `styles.ts:198-202` 的内边距与文字宽度估算，该行约 **980px**。后果：面板 <980px 时「汇率」「刷新」被推出卡片右缘（`.tw-panel` 无横向滚动），只能靠外层 body 横向滚动才够得到；同一布局在自选页会换行，两页行为不一致。改法：补 `flexWrap:'wrap'`，并把「汇率/备份」收进 `MoreMenu`。验收：600px 宽面板下所有按钮可见且不重叠。`S`

### P1-4 "三源都没有价格"在界面里有四种叫法（S）
`quoteState.ts:25`（缺失）、`PortfolioPage.tsx:218`（无价）、`WatchlistPage.tsx:370` / `PortfolioPage.tsx:892`（暂无可用行情源）、`WatchlistPage.tsx:371`（暂无行情）。后果：顶部徽标说"缺失 2"、持仓页说"2 只无价"、行内说"暂无可用行情源"，用户无法确认三处是否同一件事，也就无法判断"要不要重试"。改法：统一为「无行情源」，把"暂无行情"专留给"本轮尚未取到"，四处同源（常量放 `quoteState.ts`）。验收：全局搜索这四种写法只剩一处定义。`S`

### P1-5 缺失原因只能 hover，且承载元素不可聚焦（M）
原因文本全部挂在 `title` 上：`WatchlistPage.tsx:336-341`（板块 —）、`:342-350`（α —）、`:366-370`（无行情源）、`PortfolioPage.tsx:888-893`（无价）、`TopBar.tsx:499`（四态说明）。这些 `span` 都没有 `tabIndex`。后果：键盘与触屏用户拿不到原因（Chrome 不在 focus 时显示 `title`），"缺失必须给原因"这条约定只对鼠标用户生效。改法：这类标记改 `<button>`（或加 `tabIndex=0` + `aria-describedby`），点/聚焦时在面板内弹出可读气泡；至少把原因并入 `aria-label`。验收：不碰鼠标，Tab 停在"板块 —"上能看到原因。`M`

### P1-6 四态色点对读屏不可达（S）
`TopBar.tsx:516-520` 的 `.tw-qdot` 挂了 `aria-label`，但父卡已有 `aria-label`（`:500`，不含状态），子节点 label 不进入可访问名；`.tw-sr`（`styles.ts:98`）全项目只用过一次 —— `kline.tsx:595`。后果：读屏用户只听到"XXX 实时行情，点击打开详情"，无法知道这张卡是延迟/定稿/缺失，而四态的全部意义就是"这个数字可不可信"。改法：把 `QUOTE_STATE_LABEL[st]` 并进卡片 `aria-label`（如 `上证指数 延迟 实时行情`）。验收：读屏朗读包含四态词。`S`

### P1-7 其余图表没有读屏等价物（M）
`charts.tsx:50`（Sparkline）与 `charts.tsx:190`（MiniTrend）返回裸 `<svg>`，既无 `role="img"` 也无 `aria-hidden`；`IndustryHeatmap.tsx:88` 的自绘热力图、`RescuePanel.tsx:152` 的护盘曲线同理。后果：这些图在读屏下要么被跳过、要么读成一串无意义标签；自选/持仓行唯一的"当日走势"信息因此不可得。改法：装饰性迷你图加 `aria-hidden`，承载信息的图照 `kline.tsx:586-590` 补 `role="img"` + `.tw-sr` 摘要（涨跌幅、区间、数据时刻）。验收：读屏朗读自选行时能听到走势摘要。`M`

### P1-8 宽屏两列打乱名次顺序（M）
`styles.ts:104-108` 在 ≥1500px 用 `repeat(auto-fill,minmax(520px,1fr))`，网格按行填充。后果：按涨跌幅降序后第 2 名出现在第 1 名**右侧**、第 3 名回到左列第二行；顺左列往下读会读到 1/3/5 名，名次感错乱（排序的全部意义是名次），且条目数变化时会整体重排。改法：改 CSS 多列（`column-count:2; break-inside:avoid`，天然按列竖向填满）或显式 `grid-auto-flow:column` 固定行数。验收：1200px 以上窗口按涨跌幅排序，左列自上而下是第 1、2、3 名。`M`

### P1-9 多列断点比所需宽度高 400px（S）
两列所需宽度为 `520×2+16+20=1076px`，断点却是 1500px（`styles.ts:104`）。后果：1080–1500px 区间仍是单列，`.tw-wrow .nm{flex:1}`（`styles.ts:262`）把名称与右侧行情撑开，1100px 宽面板里一行"名称 … 价格"相隔约 400px，眼睛要跨半屏对位；这一段也正是列头排序不生效的区间（P1-2③）。改法：断点降到 ~1080px（一行改动）。验收：1100px 宽下面板呈两列。`S`

### P1-10 组头下方右半边多一条分隔线（S）
`styles.ts:107` 只抹掉 `.tw-wlist>.tw-wrow:first-child` 的上边框，双列时右列首个仍带 `border-top`（`styles.ts:260`），而组头本身已有 `border-bottom`（`styles.ts:221`）。后果：宽屏下组头下方右侧出现第二条线，看起来像"右列是另一个分组"。改法：改成 `.tw-wlist>.tw-wrow:nth-child(-n+2)`（配合断点），或统一由组头画线、行不画首行。验收：宽屏截图组头下方只有一条线。`S`

### P1-11 硬编码色与主题 token 脱钩（同一含义两种颜色）（S）
`styles.ts:91-94` 的异动呼吸底色写死 `rgba(229,72,77,.10)`（浅色主题 `--tw-up` 的值），而行内竖条用 `var(--tw-up)`，深色主题下是 `#ff5f6d`（`styles.ts:29`）—— 同一条边两种红；`IndustryHeatmap.tsx:26` 写死 `229,72,77 / 39,166,68`；`index.tsx:245-250` 侧栏徽标四色写死（`up:#ff5f6d` 是**深色**主题的红、`flat:#6f7787` 是浅色主题的灰），浅色主题下徽标红与面板红不同；提示琥珀色还有两套：`#e0a94a`（`TopBar.tsx:430/440/444`、`WatchlistPage.tsx:369`、`ui.tsx:148`、`RescuePanel.tsx:572/632`、`quoteState.ts:31`）与 `#e8a33d`（`PortfolioPage.tsx:268/878`、`CalendarPage.tsx:20/333`、`kline.tsx:17/164`）。后果：深色主题下异动行左条与底色不是同一个红、热力块与同页文字涨跌色不同；浅色主题下侧栏徽标偏粉；同类"注意"提示两种橙。改法：异动底色改用 `var(--tw-up-bg)`/`color-mix()`，热力图 base 取 token 值，琥珀统一为一个 token（顺带解决 P2-1 的对比度）。验收：深浅两主题各截一图，同义色值一致。`S`

### P1-12 破坏性操作与信息提示走原生对话框（S–M）
`PortfolioPage.tsx:347/388`、`CalendarPage.tsx:353` 用 `window.confirm`，`PortfolioPage.tsx:385` 用 `window.alert` 做纯信息提示（"请先卖出全部数量"）。后果：深色主题下弹出系统浅色对话框，与面板脱节；同一个项目对"导入"做了校验→差异预览→确认两段式（`PortfolioPage.tsx:526-576`），对"归档分组/移除持仓"却只有一句确认，安全标准不一致。改法：`window.alert` 改 toast/inline 提示；`confirm` 改 `Modal`（复用 `Field`/`Btn`）。验收：归档分组在深色主题下弹出面板内对话框。`S/M`

### P1-13 排序键名与列名随口径漂移（S）
`sort.ts:30` 固定 `pnl: '持仓盈亏'`，而列名随口径在"持仓盈亏/浮动盈亏"间切换（`PortfolioPage.tsx:297`、`:915`）。后果：切到均价口径后列叫"浮动盈亏"、排序键仍叫"持仓盈亏"，用户会怀疑排的是另一个数（`sort.ts:50` 的 hint 才说明口径跟随）。同类问题还有 `sort.ts:33-34` 新增的「现价/成本」键 —— 行内并没有这两列。改法：`SortBar`/`SortHeader` 的 label 跟随 `prefs.costBasis`（"盈亏（摊薄）/盈亏（均价）"），并把"列名"与"行内字段名"用同一常量。验收：切换口径后两处文案一致。`S`

### P1-14 弹窗/抽屉没有对话框语义，也没有焦点管理（M）
`ui.tsx:19-28` 的 `.tw-modal` 与 `QuoteDrawer.tsx:355` 的 `.tw-drawer-mask` 都没有 `role="dialog"`/`aria-modal`/`aria-labelledby`（全仓 grep 无 `role:'dialog'`），没有焦点陷阱，关闭后不还焦；只有 Escape 关闭（`ui.tsx:13-18`、`QuoteDrawer.tsx:109`）。后果：弹窗打开时按 Tab 会走到背后的页签与行上；用键盘"移除持仓"确认后焦点丢失，要重新 Tab 十几步才回到那一行。改法：加 `role="dialog" aria-modal="true"` + 标题 id 关联；打开时聚焦首个控件，关闭时把焦点还给触发元素。验收：键盘完成"打开 ⋯ → 移除持仓 → 关闭"后焦点回到该行。`M`

## 四、可选（风格偏好，可不动）
