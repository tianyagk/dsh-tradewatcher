## 一、实际不可用 / 半可用（需处置）

### A1 本地归档拼接只对"国际指数 / 商品 / 期货"生效；沪/深与港股/美股的归档是纯浪费
- **声明**：README「分时」节——"港/美股、国际指数、外盘商品、期货这些**没有多日分钟源**的市场，五日档改用本地归档拼接（v0.31.0 起）"；`em.ts:1313-1321` 的分支顺序。
- **实际行为**：分支 1（`fetchMultiDayTrend`）之后有 `if (multi !== null && multi.points.length > 1) return multi`（`em.ts:1318`），而 `multi` 的兜底源是 `tencentTrend`（`em.ts:1037`，路由未传 `fallbackSource`，`routes.ts:521`）。于是：
  - 沪/深：新浪 5 分钟线直接给 5 天（实测 240 点）→ 分支 1 命中，不拼接；
  - 港股/美股：`fetchMultiDayTrend` 因 `sinaSymbol()===null` 返回 null（`em.ts:1278-1280`），但兜底源 `tencentTrend` **给的是当日 272 点** → 仍命中分支 1 ⇒ **只要腾讯分钟线可用，五日档就只显示当天**；实测 116.00700 的回包没有 `coverage`、`trends-lkg.json` 的 `116.00700|5` 槽存的也是当日数据；
  - 只有 `sinaSymbol===null` 且腾讯也不认的市场（100.SPX 等国际指数、101/112 外盘商品）才落到 `stitchFromArchive`（实测 `source: "local-stitch"`）。
- **为什么是问题**：`trends/` 里 54 个标的目录中 45 个只有 1 天，而其中绝大多数（沪深 + 港股 + 美股）的归档**永远不会被读取**；用户看到的"仅当日（该市场无多日源）"其实对港股/美股是**错的**——它们有归档，只是被当日数据短路了。
- **建议**：把"当日数据"与"多日数据"分开判定（例如按 `trendDayCount(points) >= 2` 才认分支 1），让港股/美股也走拼接；或明确停掉这些市场的归档写入（省磁盘）。
- **验收**：对一只已归档 ≥2 天的港股打开五日档 → 断言 `source === 'local-stitch'` 且 `coverage.have.length ≥ 2`；或断言归档目录不再增长。

### A2 五日档的"覆盖率"极低：54 个标的里只有 7 个达到 5 天
- **声明**：README「本地按日归档 + 拼接（v0.31.0 起）」——"每天打开一次该标的即可 +1 天"。
- **实际行为**：实测 45/54 只有 1 天、2 个 2 天；只有 7 个（沪/深）达到 5 天 —— 且这 7 个是**靠上游多日源**拿到的 5 天，与归档无关。真正依赖归档的国际指数/商品**最多 2 天**。
- **为什么是问题**：功能的成立条件不是"时间过去"，而是"用户连续 5 个交易日逐一看过同一只标的"；对自选里几十只标的，实际达成率接近 0。它现在的观感更像噪声（一行"1/5 天 · 从本版起累积"）。
- **建议**：要么在自动刷新的路径上顺带归档自选标的（把"必须手动打开"去掉），要么如实把文案降到"仅当日（本地归档累积中，N 天）"并在 ≥3 天前不必出现"5 天"字样。
- **验收**：连续两个交易日只打开一次面板（不开详情）→ 隔日断言归档天数 +1（证明归档不再依赖手动打开）。

### A3 `coverage.missing` 会把国内休市日算成缺口，且整串日期塞进常显口径条
- **声明**：`trendStitch.ts:96-100`——只按 `isWeekday` 跳过周末；tooltip 里承认"本插件没有交易日历，节假日也会列在这里"（`QuoteDrawer.tsx:391`）。
- **实际行为**：实测 100.SPX 的 `missing` 一次列 **11 个日期**，界面按 `缺 ${cov.missing.join('、')}` 全部拼进那一行（`QuoteDrawer.tsx:350-352`）——一行里十几个日期，正是用户要"简洁"时最刺眼的那种。对**国内期货**这类真正在国内休市日停盘的标的，长假还会被误报成缺口。
- **为什么是问题**：把"没打开过"和"休市"混在同一个列表里，用户看不出"到底缺几天、是不是坏了"；而这行还是常显文本。
- **建议**：`missing` 只列**最近 5 个交易日**内的缺口并折叠为"缺 3 天（09-25、09-28、09-29）"；对节假日按"≤7 天连续空档 + 周末"启发式标注（或直接写"另有 N 天无数据"）。
- **验收**：给一个 have=2 / 区间 11 天的用例 → 断言常显文案长度 ≤ 40 字且缺失日期最多列 3 个。

### A4 板块/资金排行在备用源下没有排序键，"按金额"这一档没有效果
- **声明**：README「板块/资金排行」——金额与占比两种排序可切，且"占比排序只在本页 40 条内重排"。
- **实际行为**：实测 `/board?scope=industry&sort=money` 回 `source: "tencent"`，**每行的 `money` / `amount` / `vol` / `chg` / `up` / `down` 全是 `null`**（只有 `pct`/`price`/`leader` 有值）。界面会说"东财行情接口暂不可用，板块涨跌来自腾讯备用源"（`MarketPage.tsx:350-353`）✓ 但没有说"该源没有金额字段，所以'按金额'这档现在等同于没有排序效果"。
- **为什么是问题**：用户点"按金额"，列表顺序不变（或按上游给的涨跌幅顺序），看起来像排序坏了；这是"看着能用其实只有部分数据"的典型。
- **建议**：`source !== 'em'` 时把"按金额/按占比"置灰并在 title 说明原因（与复权段控"不适用"同一手法）。
- **验收**：模拟 `source='tencent'` → 断言两个金额类排序入口为禁用态且给出原因。

### A5 家数自统计（源 B）：至今**零次成功**，有效性未证
- **声明**：README「涨跌家数」——"优先用上游直接给的，拿不到时由本插件自行按沪深A股全量统计"。
- **实际行为**：宿主已重启到 v0.38.2（`lib/index.js` mtime 21:36，回包文案已是新版的"源A…；源B…"），说明**代码路径确实执行到了源 B**；但实测每次都被上游熔断挡住：`源B 东财 clist：首页取数失败：Error: 上游暂时不可用（熔断中，约 2 分钟后自动重试）` ⇒ `current:null`。
- **重启后必须复验的点**（静态检查**不算**"有效"）：
  1. 东财可达时源 B 是否真的返回数（上一轮报的 `total` 与有效行数不等的问题是否已修，需看是否所有行都有有效 f3）；
  2. 源 B 成功时页面三格是否真的显示自统计数（上一轮 P0-1：三格只读指数行情）；
  3. 缓存 120s 内 `asOf` 是否用"统计完成时刻"而非复用行情时刻。
- **建议**：在 `/health` 或大盘页加一个"自统计上次成功时刻"，否则这条链是否活着只能靠看回包。
- **验收**：东财可达时 `curl /tradewatcher/breadth` → 断言 `current.source === 'em-clist'` 且三格显示该数（需先修 P0-1 的接线）。

## 二、可用但界面没说清

- **B1 自绘云图在备用源下整图空白**：`IndustryHeatmap.tsx:30` 按 `amount` 取数、`:49` 只让"成交额为正"的行参与布局、`:73` 报"40 个板块无成交额，未计入面积"，同时 `:64` 显示"来源 tencent"。实测备用源下 `amount` 全 null ⇒ **图上没有任何块**，只剩两行说明。原因说了，但用户读到的是"云图空白 + 一堆术语"，建议在"可用块为 0"时直接给一句"当前板块数据来自备用源、没有成交额字段，云图不可用（切换来源：等待东财恢复）"。
- **B2 备用源的作用范围没有汇总入口**：`MarketPage.tsx:344` 在板块区显示"来源 tencent"，但云图、板块、涨跌家数、分时各自的来源散落在四处；"现在到底有哪些数据是降级的"只能逐块看。建议在面板标题处加一枚统一的"备用源中"徽标（点击展开清单）。
- **B3 细节卡片的口径标签**：`chartCursor.ts:203-225` 的分时读数是"时间/价格/涨跌幅/均价/成交量/成交额"6 行，缺失写 `—` ✓ 内容永远存在；标签统一叫「涨跌幅」，具体口径（距开盘/距首点/同日开盘）只在 `hint`（title）里（`chartCursor.ts:207-214`，v0.37 的决定）。**风险**：跨日拼接时"距首点"与"距当日开盘"是两个不同的数，可见文本完全相同，只有 hover 才能分辨。建议跨日档在标签后加一个极短的区分符（如 `涨跌幅（首日）`）。
- **B4 ±% 刻度列的条件**：`kline.tsx:240` `pctScale = isUsableBaseline(baseline) && session !== null` ⇒ 无昨收或无数时段表时右侧不留那列（有意设计）。但**用户看不出"为什么这次没有右侧刻度"**；建议在口径行里补一句"（无昨收基准，不显示 ±% 刻度）"。

## 三、有效（实测确认能用）

- **YTD**：实测 4 只（含 ETF、指数）全部有数；指数走 `fq:0 / fqSupported:false`，回落原始价格 ✓；基准 `2026-01-05`、`baseKind:'year'` ✓。
- **沪深五日**：上游多日源给满 5 天 × 48 点 = 240 点（实测），无需本地归档 ✓。
- **护盘信号**：休市时段实测仍给 `level:1 / score:36 / 因子 4/6`、7 条通道、`activeWindow{reason:'closed', nextLabel:'10-12 09:25', samples:369}`，并在 summary 里写明缺哪两个因子 ✓（非交易时段显式态有效；通道 `superNet` 为 null 时该通道只是缺资金流，不是空壳）。
- **备份导出**：`/tradewatcher/backup` 实测 `ok:true`、`unreadable:[]`、含 watch/positions/ledger/prefs 四文件 ✓。
- **日历**：实测 1368 条（宏观 1129 / IPO 48 / 财报 34 / 分红 7 / 其他 150），`syncedAt` 为当天 ✓。
- **排序（段控）**：入口唯一（v0.36.0 删掉列头，净 −183 行）✓；无效值恒沉底、同值稳定由 `sort.ts:106-118` 的索引比较器保证 ✓。
- **归档清理**：`trendArchive.ts:139-151` 只删 `YYYY-MM-DD.json`，实测目录结构与名字模式一致 ✓ 不误删。

| 功能 | 成立条件 | 不成立时的表现 | 界面说清了吗 |

## 不确定

1. **源 B 是否真能跑通**：本轮只看到"执行到 clist 但被熔断挡住"，成功路径从未真机验证（A5 已单列）。
2. **港股/美股归档是否真的完全不被读取**：结论基于 116.00700 单点实测 + 代码分支顺序；`106.XLK` 等 0 归档标的未逐个验证。
3. **A3 对国内期货的误报**：结论来自"国庆期间国内休市"这一事实 + `isWeekday` 只跳周末；未构造 113/114 标的的实际拼接样本。
4. **A4 的排序行为**：实测到 `money/amount` 全 `null`，但"列表顺序是否等同未排序"未取两次对照快照确认。
5. 细节卡片在极窄宽度下的可用性、`session` 表未覆盖市场（美股/商品的时段漂移）的表现未验证。
6. **空自选 / 空持仓 / 空账本**下的表现未实测（需改动用户数据，超出只读范围）；实测路径只覆盖了"有数据但上游熔断"这一侧。
