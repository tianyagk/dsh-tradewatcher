# 竞品对照记录：爱盯盘（浏览器扩展）

本文件记录对竞品「爱盯盘-股票盯盘-基金助手」的**可验证**观察，以及由此得出的取舍结论。
结论会被吸收进 [`ROADMAP.md`](ROADMAP.md)；本文件保留原始证据，便于日后复核（竞品会改版）。

采集时间：2026-10-08。竞品版本：Edge 商店 manifest **2.36.0**（开发者「面壁投基」，4.9 分 / 36 评 / 7688 装机）。

## 一、源码可得性：闭源

| 尝试 | 结果 |
| --- | --- |
| Edge 商店详情接口（`getproductdetailsbycrxid/<crxId>`） | 拿到完整 **manifest** 与描述/更新日志 |
| GitHub 搜索（作者名、产品名、crxId、`aidpan`） | 作者 `dapanyuntu` 名下两个仓库；`git clone` 验证 **只有一个 2906 字节的 README.md，无任何代码**；另一仓库 main 分支树为空 |
| 第三方同名仓库 | `sevenshal/52etf`（Python，13 MB）非本插件 |

**结论**：扩展本体是 MV3 构建产物（`index.html` + `content.js` + `background/background.js`），源码未公开。
因此"实现方式"的结论只能来自 manifest 与官方自述 —— 好在 **manifest 的权限清单比宣传文案更诚实**。

权限：`storage / windows / alarms / contextMenus / scripting / notifications`；
`content_scripts` 注入 `<all_urls>`；`commands` 绑定 `Ctrl+I`。

**旁证价值**：`fundgz` 出现在线上 manifest，说明该源在其生产环境可用 —— 本仓库 ROADMAP 里 P1-14（场外基金估值）挂着"待探活"的那个源。但"有人在用"不等于字段口径已确认，**不据此猜解析**。

### 架构上的不可比部分

`windows`（窗口置顶/置底）、`scripting` + `<all_urls>` 内容脚本（跨页面注入）、角标（`action` + `alarms`）——都依赖**浏览器扩展形态**。dsh 插件是 Web 面板，没有这些能力。本仓库 ROADMAP 已把这类列为「不进清单」，理由充分，不再评估。

## 二、官方截图的三点观察（`/tmp/aipan-{1,2,3}.jpg`，1280×800）

| 图 | 页面 | 关键结构 |
| --- | --- | --- |
| 1 | 自选 | 6 张指数卡（填充底色）→ 分组 chips + 🔍 → **表格**：`Name / 总市值 ⇅ / 最新价 / 当日涨跌 ⇅ / 年初至今 ⇅ / ↻`；每行 sparkline、`☰`、`♡` |
| 2 | 持仓 | 顶部三数汇总（总市值 / 浮动盈亏 / 当日盈亏）→ 账户 chips（东方财富 / 价值投资）→ 表格：`股票/市值 ⇅ / 盈亏 ⇅ / 当日盈亏 ⇅ / 成本/现价 / 持仓股数 / 仓位比 ⇅ / 操作`；**成本与现价合并一格**（`30 / 35.59`）；空仓行是「输入成本价 / 输入股数」手填单元格 |
| 3 | 行情 | 北向 / 南向 sub-tab → 合计净买入 + 沪股通 + 深股通 → 多序列分时（图例、Y 轴亿元、悬停十字线 + 数值气泡） |

**可取**：真表格 + 列头 `⇅` 排序（比"选排序键"更贴表格直觉）；涨跌幅用**填充色块**（扫读最快）；成本/现价合并一格；`仓位比` 独立成列。

**要避免**：同一产品里**两套涨跌配色** —— 其云图官网 README 明写「**红色表示下跌，绿色表示上涨**」，而扩展列表是红涨绿跌（图 1 的 `+0.37%` 红块、`-24.58%` 绿块；图 3 的 `合计净买入 41.23亿` 红）。这对 A 股用户是反直觉负担。

> ⚠️ 本仓库当前**也犯了同一个错**：`CloudMap.tsx` 渲染自绘热力图时把 `redUp` 写死为 `true`，不读 `prefs.redUp`；第三方 iframe 又是它自家的红跌绿涨。即同一面板内可能出现三种相反的色义。已记为必修项（见 [`AUDIT-UI.md`](AUDIT-UI.md) 必修 1），批二修复。

## 五、结论：借什么、不借什么

**借**（已进 ROADMAP）
1. 列头点击排序（自选 + 持仓，保留分段开关与键盘可达）。
2. 年初至今列（前复权序列算，缺失显示 `—`）。
3. 云图时间轴复盘（需每日热力图快照，与 `breadth.json` 同一层机制，可合并设计）。

**不借**（附理由）
- 置顶/置底、跨页面注入、角标数字：依赖扩展形态，Web 面板做不到。
- 多券商账户分级：本仓库的"分组"已覆盖组织语义；引入账户会计主体等于引入一套新的对账口径，收益不抵复杂度。
- **行内直接改成本/股数**：竞品的持仓是手填的（唯一数据源）；本仓库的数量与成本**全部由流水推导**，允许直接改会破坏可审计性与"账本重放一致"这条硬约束。改动请走「买/卖/调整」，这本身就是设计选择而非缺失。
