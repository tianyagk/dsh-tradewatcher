## 第 1 段：批量粘贴录入（P2-9）

- **入口**：放进持仓页分组「…」菜单（`{ label: '批量录入' }`），**没有新增常驻按钮**（开发原则 1）。
- **三步模态** `src/client/BulkPaste.tsx`：`① 粘贴 → ② 预览 → ③ 完成`，标题右侧显示当前步。
  - 文本框 + 落点分组下拉（默认当前分组，取 `archive` 之外的分组）；摘要一行（`可写入 N 条 · 建仓 a · 买入 b · 卖出 c · 报错 d 行`）。
  - 预览表列：行 / 代码 / 名称 / 日期 / 数量 / 价格 / **记为**（`建仓（买入）` / `买入` / `卖出`）。
  - **解析失败逐行报错并保留原文**（`第 N 行：<原因>` + `<code>原文</code>`），原文可复制回去改。
  - 写入：`api.mutatePortfolio`（`addPos` → `buy`/`sell`）—— **只走既有账本写入路径，不自己写文件**。
  - **一次撤销**：每条写入的 note 带批次标记 `批量录入#<id>`，撤销调宿主 `deleteLedger` 按前缀反删；
    宿主侧把删掉的原件摘要写成一条 `pnote`（**留痕**，可追溯）。
  - **键盘**：`role=dialog` + `aria-modal` + `aria-label`；打开即聚焦首个控件；`Tab` 在模态内循环（首尾相接、焦点被拖出也拉回）；
    `Esc` 关闭（`Modal` 之外由宿主 `tw-mask` 的 Esc 处理）；关闭后由界面把焦点还原到「…」菜单触发器。
- **解析层** `src/client/bulkPaste.ts`（纯函数，7 条断言）：五种分隔符（`|`/`｜`/Tab/`,`/`，`）、列数不足/过多、
  空行跳过、完全重复行、非数字、两种日期格式（`YYYY-MM-DD` 与 `YYYY/MM/DD`，单位数归一）、
  **与逐条手工录入字段级等价**（`{secid,name,qty,price,ts,note}` 逐字段 deepEqual；`ts` = 当日 15:00）。
  另外两条产品判断：**卖出但本地无持仓 ⇒ 直接报错**（托管侧必然失败，提前说清楚）；连续分隔符**不合并空列**（合并会让列错位）。

### 实测：批量写入 → 撤销的往返一致（真实宿主，临时目录）
```
写入前（分组+持仓 2 条本地记录）： { buy: 0, sell: 0, pnote: 0, total: 2 }
写入 3 条（两买一卖，卖出放次日以符合 T+1）： { buy: 2, sell: 1, pnote: 0, total: 5 }
撤销（deleteLedger notePrefix=批量录入#test）： { buy: 0, sell: 0, pnote: 1, total: 3 }
落盘后新实例再读： buy = 0（交易条数确实还原）
留痕： 撤销批量录入：反删 3 条交易流水（Emv3a4qbg00053uxy、Emv3a4qbi0006knsa、Emv3a4qce0007hcpu）
```
即：交易流水**精确还原**，额外留一条 `pnote` 作为撤销痕迹（这是"留痕"要求本身，不是残留）。

## 追加（task-49）：五日档的"滞后优先 + 语义诚实"

**问题**：`122.XAU` 的真实归档只有 `2026-09-24` 一天（462 个点，06:00~13:41），而今天是 10-11 —— 口径行写
`本地拼接 1/5 天（仅当日，从本版起累积）`，用户第一眼读到的却是"这是最近五日的走势"。与"看着正常的错数"同类。

**改法**（判据与文案都在新纯函数 `src/shared/trendCaliber.ts`，有 6 条断言）：
1. **滞后优先**：最新数据日不是最近预期交易日 ⇒ 口径段以 `数据滞后 N 天（最近一次成功快照 …）` 开头；
2. **语义诚实**：不足上限时写 `仅 N 天可画`（只有 1 天时必写）；档位名保留「五日」（未改名，见"取舍"）；
3. **陈旧判据**：自然日差 + **工作日近似**（跳过周末、**无节假日日历** ⇒ 如实标注是近似），近似工作日 ≥2 判陈旧；
   触发时加滞后前缀 + 一句 `陈旧：图表按真实点画，不插值、不延长`；**不因陈旧而不显示**；
4. **footer 补快照时刻**：`本地缓存（最近一次成功快照 09-24 13:41）`（与口径行共用同一个 `snapshotLabel()`）；
5. `1/5 天` → `归档 1 天（本插件无多日源，逐日累积）`（括注一行）。

### 改前 / 改后（真实归档 `122.XAU`，2026-09-24 一天）
```
【改前】口径行：五日 · 不复权（分时序列无除权概念） · 截至 09-24 13:41 · 本地拼接 1/5 天（仅当日，从本版起累积） · 缺 09-25、09-28、09-29、09-30、10-01、10-02、10-05、10-06、10-07、10-08、10-09 · 无固定交易时段
【改前】footer：昨收 — · 13:41 · 本地缓存

【改后】口径行：五日 · 不复权（分时序列无除权概念） · 截至 09-24 13:41 · 数据滞后 17 天（最近一次成功快照 09-24 13:41） · 仅 1 天可画 · 归档 1 天（本插件无多日源，逐日累积） · 缺 09-25、09-28、09-29，另有 8 天 · 陈旧：图表按真实点画，不插值、不延长 · 无固定交易时段
【改后】footer：昨收 — · 13:41 · 本地缓存（最近一次成功快照 09-24 13:41）

陈旧判据：自然日差 17 天 · 工作日近似 11 天 ⇒ stale = true
```

### 四条断言（实测全绿）
① 最新=今天 ⇒ **不加**滞后前缀、无陈旧提示（非恒输出）；② 差 17 天 ⇒ 前缀 + `仅 1 天可画` + 快照时刻都在，
且滞后排最前、旧写法 `1/5 天` 不再出现；③ 差 1 自然日（周末）与差 1 工作日 ⇒ **不误报**陈旧；
④ 缺口用 `missingBrief` 短形（`缺 09-25、09-28、09-29，另有 8 天`，≤40 字，不铺 11 个日期）。

### 顺手修的两处
- `caliberExplain` 里一处**跨行模板的 `**` 泄漏**（`归档**从本版起累积**`）——旧扫描规则只看"同行有引号"漏掉了它；
  扫描规则已升级为"剥注释 → 去掉合法指数运算符形态 → 剩下的 `**` 全算泄漏"，并自检（跨行模板 ⇒ 1 处、指数运算符 ⇒ 0 处）。
- 界面曾在算滞后时 `label.slice(0, 5)`（把 `2026-09-24 13:41` 截成 `2026-` ⇒ 滞后判定**静默失效**）。改为传原始 label、
  解析放在 `dayNumberOf` 里，并加断言钉住这个坑。
