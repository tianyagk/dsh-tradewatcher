### ② 的真因（不是"取错峰值"，是**两套尺度**）
条宽按 **`peak`** 归一（峰值 ⇒ 100% 宽），刻度按 **nice 取整后的 `top`** 归一（如 8.05% ⇒ 10%）
⇒ 同一个"100% 宽"在两种尺度下含义不同：**≥8% 的条顶满整宽，而刻度说那是 10%** ⇒
小条被读成"不到 2%"、最高条被读成"顶到 10%" ⇒ 用户看到的"分布压扁在左侧"。
叠加一个**真实的坐标 bug**：竖网格线位置写成 `calc(${pct}% − ${pct*44}px)`（减掉标签宽度）⇒ 每条网格被拉左最多 44px，
与上面的刻度标签对不上（这次一并修掉）。

## 二、改动

1. **价格轴裁剪（`massWindowOf`）**：口径 = **先按筹码质量 99% 覆盖**从两端往内丢桶，
   **再隐去权重 < 窗口峰值 20% 的稀疏行**；被裁掉的质量**如实计入 `dropped`** 并写进 tooltip（不静默）。
   实测 601872：**改前 5.47–22.82 / 96 行 / 1px 每行 → 改后 14.05–22.64 / 48 行 / 2px 每行（覆盖 97.35%，轴外 2.65%）**
   —— 与券商观感的 13.7–23.3 同一量级。
   ⚠ **没有**做任何"按峰值归一/整体拉伸"：权重数组原样使用（`sum = 1` 守恒断言仍在），只是**少画**轴外与稀疏行。
2. **横轴与条宽同源同尺度（`chipAxisOf`）**：导出**唯一来源** `{ peak, top, ticks, window, widthOf }`；
   条宽改为 `widthOf(w) = w / top × 100%`（**按轴顶**，不是按峰值）⇒ 峰值条宽 = peak/top（如 3.99/4.00 = 99.8%），
   与刻度同一尺度；刻度集覆盖到轴顶、从 0 起步；**峰值为 0 ⇒ 不出刻度**（`top = 0`、`widthOf ≡ 0`）。
3. **网格线位置修 bug**：`left: ${pct}%`（去掉 `− pct×44px` 的偏移）。
4. **口径文案**：`methodology` 写明裁剪两段口径；tooltip 增加"显示区间覆盖 xx% / 轴外 xx%"与"轴顶 xx%（当前展示日单桶峰值 xx%）"。

## 三、断言（新增 `src/client/chipAxis.test.ts`，3 条）
```
① 覆盖面：裁剪后 covered ≥ 0.95（组合口径下阈值可能先咬住，故用 95% 兜底）+ covered + dropped === 1；
   窗口内权重之和 === 原值（证明**没有归一化拉伸**）；裁剪区间在原区间内；全 0 / 空输入不抛错
② 同源同尺度：peak === 当前展示日单桶最大权重；峰值条宽 === peak/top×100 且 **≠ 100%**（≠100% 正是"不再按峰值归一"的判据）；
   刻度首项 = 0、末项 = 轴顶
③ 自适应与极值：换一天（峰值 2% → 8%）⇒ 刻度集不同；峰值为 0 ⇒ 不出刻度、widthOf ≡ 0；
   单桶 100% ⇒ 轴顶 ≥ 100%、条宽 ≤ 100%、刻度正常；空/NaN 输入不抛错
```
