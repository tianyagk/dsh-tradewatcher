## 2. 可发现性：信息架构、空状态、快捷键

### 2.1 现状（**事实**）

- **页签是 6 个，不是 7 个**【事实】：`src/client/index.tsx:189` 的 `PageKey` = `watch | portfolio | market | cloud | calendar | tools`；`:371-378` 的 `tabs` 数组 6 条（自选 / 持仓 / 大盘 / 云图 / 日历 / 工具），每条的 `row` 对应七行里的功能行。"七"指**行**（6 功能行 + core），不是页签。
- **工具目录当前只有 1 个工具**【事实】：`src/client/toolRegistry.ts:215` `TOOL_ENTRIES = [cakeTool]`，而 `ToolsPage.tsx` 的目录区就是按这个数组渲染 ⇒ **一个卡片占一页**，且该页签是"六分之一"的一级入口。
- **快捷键**：`Alt+M` 切换视图模式（完整/紧凑/隐身）【事实，`src/client/index.tsx:255-270`】；但它对用户**只在一条 tooltip 里出现**【事实，`src/client/TopBar.tsx:447`】⇒ 一级功能（隐身视图）的**唯一入口是隐藏快捷键**【推断：绝大多数用户找不到】。
- **空状态**：统一组件 `EmptyHint` 只在 3 个页面用了【事实，`WatchlistPage`/`PortfolioPage`/`ToolsPage` 各 2 处】；`MarketPage.tsx`、`CalendarPage.tsx`、`CloudMap.tsx` **没有**任何 `EmptyHint` 【事实】⇒ 这三个页在"没数据/未加载"时靠各自的「未取到」提示撑着（诚实 ✓，但**不像空状态**，用户不知道下一步能做什么）。
- **详情入口**：详情抽屉（`QuoteDrawer`）由行点击/键盘 Enter 打开【事实，`MarketPage.tsx` 的 `onClick/onKeyDown` 与 `api.detail`】⇒ 入口存在但**没有任何可见提示**（除工具箱那页的"点行看详情"【事实，`MarketPage.tsx` 的指数表已按用户要求删除后，这类提示更少了】【推断：新用户不会想到点行】）。

### 2.2 建议

1. **工具目录：1 个工具时不留一页空白** —— 目录区在有 ≤2 个工具时**降级为"工具列表 + 说明"**（列表就是那 1 张卡，下面接一段"这个页签会随工具增加而变长"的**一次性**说明，用 `prefs` 记"已看过"），**不新增常驻长文案**。⇒ 不新建页签、不新增数据源。
2. **快捷键要能被发现**：把 `Alt+M` 写进 TopBar 那个视图按钮的 `title`（已有）+ 在**帮助面板/工具页**里列一条"键盘"小节（1 行）；**不新增常驻横幅**。
3. **给 3 个缺空状态的页面补 `EmptyHint`**（复用既有组件）：大盘页="行情引擎未就绪（首次启动约 5 秒）"、日历页="本月无事件（可切换月份）"、云图页="板块数据未取到（原因见悬停）"。
   ⚠ **不得**把"未取到 + 原因"换成"暂无数据"这类含糊词（红线：缺失原因必须保留）。
4. **详情入口可发现性**：给可点击行加**一致的**视觉提示 —— 行 hover 时行尾出现"详情 ›"（纯 CSS，`::after`），并在页面级只保留**一处**极短提示（如自选/持仓表头右侧的"点行看详情"6 字，与工具箱页现有一致）。

### 2.3 可检查阈值

- 断言：`TABS.length === 6` 与"页签数 == 行的功能页签数"（负例：加第 7 个页签必须失败，防止偷偷塞入口）。
- 断言：三个页面各自至少有一个 `EmptyHint` 分支，且其文案**不含**"暂无数据"这类无原因词（负例：把 `EmptyHint` 文案改成 `暂无数据` 必须失败）。
- 断言：`Alt+M` 至少出现在 **2 处**（行为 + 一处可见说明）（负例：删掉说明 ⇒ 失败）。

### 2.4 影响面与风险

- 4 处改动，全部在客户端；预计 **≈60–90 行**（含 2 条新断言）。
- 风险：空状态与"未取到"语义容易**重叠/打架** ⇒ 规则要写死：**引擎/上游问题 ⇒ 「未取到 + 原因」；用户自身状态（没有分组、本月无事件）⇒ 空状态 + 下一步动作**。这条规则要进断言，否则以后会退化成"两种都说"。

## 3. 形态扩展：迷你窗 / 玻璃浮窗能不能做

### 3.1 宿主取证（**事实**，读宿主产物）

- **存在浮层挂载点**：宿主 `@deepseek-ai/dsh-client-ui-layout` 的 `lib/types/client/AppFrame.d.ts:4` 渲染槽位
  `'sidebar' | 'main' | 'rightbar' | 'shell.bottom' | 'shell.overlay' | 'shell.leading'`
  ⇒ **`shell.overlay` 是根级浮层槽位**（"网页内浮窗"这一形态在宿主模型里**有位置**）。
- **不存在"同一面板的第二实例"**：同包 `service.d.ts:14-32` 的 `MainPanelId` / `selectPanel(panelId)` 语义是**单选**
  （"Selected global panel; null displays the current Conversation"，"`@throws` if the selected main key is not registered"）
  ⇒ `main` 是"当前选中的那一个面板"，不是可并排/可重复实例的容器。
- **"第二个面板"是允许的**：`dsh-client-ui-sidebar` 的 `lib/types/client/contract/slots.d.ts`：`sidebar.panellist` 是 `kind: 'list'`，
  "Each list id addresses the matching main panel" ⇒ **一个插件可以注册第二个 `main` key + 对应侧栏图标**（形态上是"另一个面板"，不是浮窗）。
- **本插件现在的挂载方式**（我们自己的代码，**事实**）：`src/client/index.tsx:103-118` 只注册了 `sidebar.panellist`（图标，id=`tradewatcher`）与 `main`（key=`tradewatcher`）两个槽位。
- ⚠ **未能在线验证**：本次会话的客户端页面未连接 ⇒ 无法用 live Slot 检查确认**本部署**是否开放 `shell.overlay`（我用 Inspect 查询时返回 "no connected Harness page"）⇒ `shell.overlay` 的**可用性**标 **【推断】**，可用性需开一次页面用 Slot 检查或让用户确认。

### 3.2 结论：可做 / 不可做

| 形态 | 结论 | 依据 |
|---|---|---|
| 同一面板的**第二实例**（两个 `tradewatcher` 并存） | **不可做** | `main` 单选（`selectPanel`） |
| **第二个面板**（新的 `main` key，如 `tradewatcher-mini`） | **可做**（低风险） | `sidebar.panellist` 是 list，"每个 id 对应一个 main key" |
| **玻璃浮窗**（浮在对话/页面上） | **结构上可做**，可用性待确认【推断】 | 有 `shell.overlay` 槽位；玻璃令牌与 `.tw-glass` 类**已存在**【事实，`docs/DESIGN-UIUX-ADOPT.md` §1.2 + `src/client/uiuxDiscipline.test.ts:108-135`】 |
| **迷你窗**（200×270 那种独立小窗） | **等价于"第二个面板 + 紧凑视图"** | 宿主没有 `chrome.windows` 类能力 ⇒ 只能落成面板/浮层 |

### 3.3 最小实现方案（三步，均**不新增取数路径**）

1. **数据侧：复用，不新建。** 浮层/迷你视图只读现有 `api.*`（`/tradewatcher/*`）与同一个行情引擎；
   **禁止**在浮层里再起一个 `useQuoteEngine`（那会变成第二条轮询路径）。
   - 硬证据与护栏已有：`src/host/fetchDedupe.test.ts` 锁"同一标的同一时刻只打一次上游"【事实】；跨形态共享还应加一条断言：**页面渲染前后，上游请求次数不变**。
2. **状态侧：复用主机半区 store。** 浮层展示的数值直接取现有 LKG/缓存（宿主半区已有落盘 LKG 与单例 store）【事实，本插件 `src/host/store.ts` 与各路由的 `stale/lastBar` 契约】⇒ 关闭浮层不影响数据；重新打开直接吃缓存。
3. **挂载与开关：** 在 `shell.overlay` 里注册一个 occupant，渲染"迷你视图"（复用既有展示组件，只换布局与字号），
   开关持久化到 `prefs`（沿用 `viewMode` 那种写法【事实，`index.tsx:255-270` 的 `api.setPrefs`】）；关闭态 `display:none`（既有动效纪律要求【事实，`uiuxDiscipline.test.ts:135`】）。
   - 若本部署没有 `shell.overlay`：退一步用**第二个 `main` key**（`tradewatcher-mini`），形态是"侧栏第二个图标 + 一个迷你面板"，同样满足"不重复取数"。

### 3.4 可检查阈值

- 断言：迷你视图**不出现** `useQuoteEngine(`/`new QuoteEngine`（负例：加入即失败）；
- 断言：开关状态来自 `prefs` 且默认关闭（负例：默认开启必须失败）；
- 断言：迷你视图用到的每个数字都能在**现有路由**里找到来源（把"来源路由"写成表并逐条 grep 命中，负例：写一个不存在的路由必须失败）。
- 人工阈值：浮层在 200×270 与 320×420 两档截图里，**不出现横向滚动条**、**字号 ≥12px**（与 §1 阶梯一致）。

### 3.5 风险

- **最大风险是"第二份轮询"**：浮层若挂在不同的 React 根，容易各自起引擎 ⇒ 上游请求翻倍（这既违反红线也会触发熔断）。
  缓解：断言 + 只在宿主半区做去重（已有 `fetchDedupe`）+ 浮层与主面板**共用同一个模块级 store**（本插件已有先例：侧栏徽标状态就是模块级单例【事实，`index.tsx:24-40` 段注释】）。
- 次风险：`shell.overlay` 在不同部署/版本上可能不可用 ⇒ 方案必须能退化成"第二个主面板"（§3.3 结尾）。

### 4.2 建议（每条只加**一句参照**，进悬停，不加常驻长文案）

1. **护盘总分**：在 `RescuePanel.tsx:452` 那格的 `title`/`aria-label` 里补"近 20 日分位 X%（样本 N 天）"与"当日最高 Y @HH:MM"。
   数据来源**必须**是现有快照字段（`snapshot.intraday` 里已有 `peak`【事实，`:609-612`】；分位若宿主已算则直接用，**未算就不显示**，不许现算一个假分位）。
2. **因子贡献列**：在表头 `title` 里补一句"每项贡献 = 权重 × 评分 × 时点系数；满贡献 = 权重 × 100"，并在列尾给一个**行内小计满分**（例如列头写 `贡献/满分`）。
3. **α 列**：短期不做"历史 α 分位"（会牵出新的历史口径）；改为**在悬停里写清参照物**："相对所属板块；同日板块涨 X%、个股涨 Y%（数据时刻 HH:MM）"。
4. **云图**：确认无图例后，加一个**3 档色标**（`≤-3% / 0 / ≥+3%`）+ 一句"颜色 = 当日涨跌幅"，并写清"灰＝未取到（原因见悬停）"。

### 4.3 可检查阈值

- 断言：护盘总分那格必须有 `title` 且含"分位"或"当日最高"二者之一（负例：删掉 title ⇒ 失败）。
- 断言：色标三档文案与阈值常量在**同一处**定义并被渲染引用（负例：色标数字写死在 JSX 里 ⇒ 失败）。
- 人工：每个"缺参照"的表列，悬停里都能读到**参照物 + 数据时刻**。

### 4.4 影响面与风险

- ≈4 处、**≈40–60 行**（含 2 条断言）。
- 风险：**分位口径**最容易变成新的"编数"来源 ⇒ 规则写死：宿主已算才显示，否则显示 `—` + 原因；**不许**在客户端现算分位（样本不足会给出噪音）。这与护盘面板既有的"样本不足不显示分位"【事实，`MarketPage.tsx:311-314` 同款处理】保持一致。
