## 1. 契约字段（命名与既有一致）

| 字段 | 类型 | 含义 |
|---|---|---|
| `continuous` | `number \| null`（可选） | 连续评分 0–100 = `raw ÷ 权重合计 × 100`；非交易时段 ⇒ `null` |
| `continuousPercentile` | `number \| null`（可选） | 近 20 日分位（0–100）；样本 < 5 ⇒ `null` |
| `continuousPercentileN` | `number`（可选） | 该分位的**样本数**（`0` = 还没有跨日样本） |
| `continuousPercentileWhy` | `string \| null`（可选） | 算不出来的**原因**（样本不足 / 冷启动 / 非交易时段 / 旧快照缺字段） |

- 宿主映射**只有一处**：`snapshotContractFields(scored)`（`rescue.ts`），采样路径用 `...snapshotContractFields(scored)` 展开；
  另外三条"非采样"路径（尚未采样 / 复盘兜底 / 持久化兜底）也**显式**补了这四个字段 + 各自原因 ——
  免得冷启动时界面拿到 `undefined`（那是"缺字段"，与"样本不足"是两件事）。
- 持久化（`stripSnapshot` / `PersistedSnapshot`）也保留这四个字段 ⇒ 收盘后重启仍能显示分位。

## 2. 客户端接线（同一批交付）

- **可见部分**（总分那一行，紧凑）：`${score}/100 · 当日峰 … · 分位 X%（N=…）`；缺数据时该处显示短标记 `分位 —`。
- **悬停（`title`）**：`连续评分 X/100 的近 20 日分位 Y%（N=z）`；缺数据时写 `连续评分的近 20 日分位：<契约里的 continuousPercentileWhy>`。
- **不现算**：面板不引用宿主的 `scorePercentile`，也没有任何排序/计数式分位实现（断言直接扫源码 + 反例注入 C3）。

## 3. 引擎版本与旧数据的关系

| 版本 | 口径 | 与旧数据的关系 |
|---|---|---|
| ≤ v0.15.0 | 分位只在宿主算，**没进契约** | 旧快照（磁盘上的 `lastSnapshot`）没有这四个字段 ⇒ 界面显示「上次快照（旧版本）里没有跨日分位字段 ⇒ 本次显示原因而不是现算」 |
| **v0.16.0** | 四个字段进契约 + 界面显示 | 出分日志里 `engine` 标 0.16.0 ⇒ 事后能分辨"这条样本当时的契约是否带分位"；旧条目仍按当时的权重/等级线解读（`ENGINE_VERSION` 注释已写明） |
