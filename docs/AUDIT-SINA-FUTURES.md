# AUDIT-SINA-FUTURES：新浪 `nf_`/`hf_`/指数 接入报价兜底层

> 基线 v0.158.0（`6b12b4d` 之后）。**只改** `src/host/sina.ts`、`src/host/em.ts`、`src/shared/model.ts`、`src/client/chartNote.ts`（出处中文名）+ 新增 1 个测试文件 + 两份文档。
> 未改 `build.mjs`（构建 73 项）、无新依赖、未 commit、未重启；实验 `DSH_HOME=/tmp/sinafut-*`。
> 侦察原始记录见 `docs/PROBE-SINA-FUTURES.md`。

**一行结论**：新浪 `hq.sinajs.cn` 的 `nf_`（国内期货）、`hf_`（外盘/现货）、`sh|sz`（指数）三族已接进**既有报价层**
（接进既有报价层：`withHostBreaker('hq.sinajs.cn')` + `fetchSinaQuotes` 的 5 条一批 + `loadQuotes` 的行情槽有效期缓存 —— 本仓库报价层用的是"槽 + exp"而不是 `ttlCache`，语义等价，不另建旁路；`source` 标 `sina-futures` / `sina-index` + `at`），
**东财在链上、失败自动切新浪**；两家都取不到 ⇒ 没有这一行 + `missing` 写「已试：东财、新浪」。
顺带修掉两个真实解析错误：`hf_*` 的"今开"一直读的是**卖价**（下标 3），`nf_*` 的昨收常为 0 导致涨跌幅恒缺。

## 1. 采用方案

| 项 | 实现 | 位置 |
|---|---|---|
| 映射 | `112.AU0/AG0/CU0/LC0`→`nf_*`；`101.GC00Y/CL00Y/NG00Y`→`hf_GC/CL/NG`；`122.XAG`→`hf_XAG`；6 条指数→`sh|sz` | `sina.ts`（`SINA_SYMBOL` + `SINA_INDEX_SYMBOL`） |
| 族判定 | `sinaFamilyOf(secid)` → `nf`/`hf`/`index`/`gb`（决定 `source`） | `sina.ts` |
| 解析 | `nf_`：价=8、开=2、高=3、低=4、昨收=5（为 0 时用昨结算 10）、量=14、时间=17+1；`hf_`：价=0、昨收=7、高=4、低=5、**开=8**、时间=12+6、名称=13；指数：价=3、昨收=2、开=1、量=8、额=9、时间=30+31 | `sina.ts:parseSinaHq` |
| 出处 | 兜底行 `source` 按族标 `sina-futures`/`sina-index`（`gb_*` 仍 `sina`），`at = Date.now()`，`time` = 上游成交时刻（解析不出 ⇒ null，不用"现在"顶替） | `em.ts:fillFromFallbacks` |
| 缺失 | 原因改成**从能力表算**的「已试：东财、新浪」（有腾讯映射时自动变成"东财、腾讯、新浪"），不手写 | `em.ts:quoteProvenance` |
| 中文名 | `sina-futures`=新浪期货 / `sina-index`=新浪指数 | `client/chartNote.ts`（`QUOTE_SOURCE_LABEL`） |

**与东财的关系**：沿用既有链（`tencent → sina → em`；`emFields` 时 `em` 提前）。
东财仍是**价格与独占字段（成交额/市值等）的主源**，Sina 只在东财（或腾讯）拿不到时补行 —— 这就是"东财优先、失败切新浪"在本仓库既有架构里的落地方式：
**不推翻 `quoteSourcePlan` 的"东财兜底"顺序**（那条顺序是给东财限流设计的，改它会让每轮多打 3 次东财）。
