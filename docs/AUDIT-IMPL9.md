# 下一轮 A：信号前瞻 + 做T配对 + 分组排序 + 索引与告警（task-44）· 实现记录

对象：`dsh-tradewatcher` v0.40.0 工作区。基线 296 条 × 2 时区；每段一跑 `npm run check`。

## 第 1 段：信号的前瞻表现（P1-1 / P1-2）

- 新纯函数模块 **`src/host/signalForward.ts`**：`forwardOf(events, bars, benchBars, benchName)`
  → 逐事件 `信号日 / 等级 / 触发指标 / 至今涨跌幅 / 同期基准涨跌幅 / 超额 / 持有期（自然日 + 交易日）/ 最新数据日 / why`
  + 汇总 `n / 胜率 / 平均超额 / 中位数`（**样本数与结果一起给**）。
- **红线落地**：① 基准与持有期**同时**给（缺基准 ⇒ 超额 `null` 并写原因，**不当 0**）；
  ② 样本 <10 照旧出数，但 `summary.note = 「样本过少（N < 10），不构成统计结论」`；
  ③ `disclaimer` 明写「这是过去 N 次信号之后发生了什么的**回顾**，不是"信号有预测能力"」「不能当买卖信号、不能外推、不能证因果」。
- **接入方式**：扩展 `tradewatcher_rescue`（不新开工具，省一个索引项），回包新增
  `forward: { subject, rows, summary, methodology, disclaimer }`；`subject` 默认 `1.000300`（沪深300 本身），
  可用 `secid` 参数指定**被观察的标的**（基准固定沪深300）；标的与基准相同时 `note` 如实说明"超额恒 0"。
- **手算对照**（测试里同源；程序输出与手算逐位一致）：
```
标的：01-10 收 100 → 01-20 收 110；基准：01-10 收 200 → 01-20 收 210
事件1（01-10，疑似护盘）：涨跌幅 (110/100−1)×100 = +10.00% ｜ 基准 (210/200−1)×100 = +5.00% ｜ 超额 = +5.00% ｜ 持有期 10 自然日
事件2（01-15，资金异动）：起点取 01-15 收 105 ⇒ (110/105−1)×100 = +4.7619%；基准 205 ⇒ +2.4390% ⇒ 超额 +2.3229%；持有期 5 自然日 / 1 交易日
退化（信号日=最新数据日）：持有期 0、涨跌幅 —（**不是 0%**），且不计入样本
基准缺失：标的涨跌幅照给、超额 —、`why` 写明"基准（沪深300）日线未取到"、样本 n=0
```

## 第 2 段：做T / 日内往返配对（P1-3）

- 新纯函数模块 **`src/host/dayTrade.ts`**：`dayTradesOf(entries)` → `rounds / unmatched / summary / methodology`。
- 三条纪律：① **保留时序方向**（`buy-first` 正 T / `sell-first` 反 T，字段里买卖价照给，方向另标）；
  ② **按次数统计**（同日两轮计 2）；③ 配不上的进 `unmatched`（数量、方向、原因都写明），**不硬凑**。
- 费用按配对数量**比例分摊**（买入费用按 qty 摊、卖出费用按 qty 摊），`净 = 毛 − 分摊`。
- **接入方式**：放进既有 `tradewatcher_portfolio` 的 `dayTrades` 字段（做T 是持仓的派生统计，与盈亏同屏读；
  新开工具只多一个索引项与一次授权确认）。
- 实测（真实账本 + 夹具）：
```
夹具：同日两轮 + 次日一轮 ⇒ count = 3（days = 2，但**次数不是天数**）；
     第一轮手算 (10.5−10)×100 − (5+5) = 40；本轮合计 = 40 + 10 + 40 = 90 ✓
先卖后买：direction = sell-first，毛盈亏 (11−10.5)×100 = 50 ✓（不再被渲染成"买入→卖出"）
数量不齐：买 300 / 卖 100 ⇒ 一轮 100 股 + unmatched 200 股（费用按 1/3 摊 = 3 + 卖出 5 = 8）✓
```

## 第 3 段：分组一屏排序 + 分档统计 + 文本分位（P1-5 / P2-1 / P2-3）

- 新纯函数模块 **`src/host/groupRank.ts`**：`rankOf(rows, notes)` → `rows / pills / bucketLine / total`；
  `textPercentile(bars, 30)` → `{ pct, delta, extreme, text }`。
- 新工具 **`tradewatcher_group_rank`**：对自选某个分组批量取数（复用既有 `fetchQuotesWithProvenance` /
  `computeTones` / `positionOfBars` / `fetchKline` 磁盘缓存，**没有新写取数逻辑**）→ 按 `情绪`（默认，五档 score 分位）/
  `位置` / `涨跌幅` 排序 → 一屏清单 + **统计药丸** + **分档汇总一行** + 每行文本分位。
- 纪律：缺失 `—` **沉底**并计入「未取到」一档；**药丸各档之和 = 总数**（断言）；文本分位**只用算得出来的**：
  新高/新低按窗口内比较，变化量算不出就不写那一段（断言用"既非新高也非新低"的震荡序列验证**不写**）。
- **真实自选分组实测**（第一个分组 14 只，涨跌幅口径，本机 LKG 行情，未探活）：
```
上涨 6 / 平盘 2 / 下跌 6 ｜ 分档行「6 只上涨 / 2 只平盘 / 6 只下跌」｜ 合计 14 = 行数 14 ✓
（逐行：中科飞测 +3.14% 上涨 … 天马科技 −6.52% 下跌）
```
- ⚠ **这次实测当场抓到一个静默错答**：第一版把**涨跌幅**（±3% 量级）塞进**分位桶**（0–100），
  结果 14 只**全部**判成「极冷」（有值、有档位、看着正常）。已修正为：分位口径用 `bucketOf`（默认），
  **涨跌幅口径必须显式传 `returnBucketOf`**（上涨/平盘/下跌三档），并加断言把这条差异钉住
  （断言里同时写明了反例：`bucketOf(3.14) === '极冷'`）。
- 断言：药丸之和 = 总数、档位边界 10/30/70/90、三档口径与分位口径不可混用、
  文本分位的新高/不写/样本不足三种情形、`bucketLine` 读序（冷→热）。

## 未做项与原因（如实）

1. **§6.5 只做了半步**：新增两工具写了 `output.schema`；既有 10 个工具的 schema 仍是 `{}`。
   原因：那需要逐个重写 render 并回归既有文本断言，收益（结构化字段）远小于风险，按任务"不要为它改 10 个工具的既有 render"执行。
2. **`forward` 的标的默认取沪深300本身**：此时超额恒 0，已在回包 `summary.note` 里如实说明并提示用 `secid` 指定标的；
   没有替用户随便挑一个"看起来更有故事"的标的（那才是编数据）。
3. **做T 只在宿主回包里**（`portfolio.dayTrades`），未做界面卡片 —— 客户端那半在下一个批次（task-45）。
4. **真实账本的做T往返很少**（149 条里少量同日往返、85 条单边未配对），样本不足时不给统计结论 —— 这是数据现状，不是实现缺陷。
5. 上一轮遗留的 `marketState` / `showing` 未在回包填值（同类：需要逐个源确认快照时刻来源）。
