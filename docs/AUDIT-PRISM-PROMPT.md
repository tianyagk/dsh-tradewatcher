| --- | --- | --- | --- |
| C1 | 骨架 vs 配置 | 「单票上限 20%，单板块上限 30%」 vs 「单票上限：30%」 | 在 20–30% 区间主动减仓；实盘模型已选择 30%，但每轮都要解释一次 |
| C2 | 骨架 vs 配置 | 骨架「单板块上限 30%」 vs 配置「单板块上限：未设置」 | 把 30% 写进 `byIndustry` ⇒ 反过来成为引擎的硬上限（见 P0-1） |
| C3 | 骨架 vs 强制 vs 引擎 | 「止损条件是叙事证伪，不是价格」 vs 「必须用买入均价判浮亏」 vs 引擎「只拒买、不卖」 | 三套止损观；叙事止损没有执行路径，价格止损只拦加仓 |
| C4 | 骨架 vs 强制 | 「不在恐慌中清仓」「宽基不割」 vs 「必须先判断是否需要降低风险暴露…若判断不减，必须写明为什么**满仓**是合理的」 | 规则把「不减」设为需要辩护的异常态，偏向卖出 |
| C5 | 输出契约内部 | JSON 里 `note` 是「一句话」 vs 强制规则要求「分两段：不买 / 不卖」 | 字段说明与规则打架，模型输出长度不稳定 |
| C6 | 候选池 vs 自选池 | 「orders 的 secid 必须来自候选池」 vs 骨架「可以在自选池中选择尚未持有的标的建仓」 | 自选里的港股/美股看得见、买不得；候选池截断后连 A 股也买不得 |
| C7 | 强制规则 vs 配置可能为空 | 「`limits.singlePct` 必须等于配置的单票上限」 vs 配置输出「未设置」 | 只能填 null（随后被 `decisionProblems` 判为不合格）或自造一个数 |
| C8 | 强制规则 vs 快照字段 | 「可用数量一律以账户快照为准」 vs 快照无「可用数量」 | 只能猜；卖单被裁后不知道为什么 |
| C9 | 去重规则 vs 回撤闸门 | 「不得原样重发被拒委托」 vs 闸门每轮以同一原因拒绝所有买单 | 要么彻底不买，要么微调价格/股数绕过去重（容差 ±0.5% / ±100 股） |

## 6. 专题：信息冗余与噪声（实测）

**先纠正量级**：实测单路 **12.7–17.4K 字符（≈8–12K token）**，不是 4–6K token；一轮 5 次调用合计 ≈78K 字符。最大两块是候选池 6.1K 与新闻 4.5K，其次是骨架 2.5K × 5 次。

单轮 = 4 路分析 + 1 次汇总，**同一份 `compileInput` 被调用 5 次**（信息面带新闻，其余不带；汇总再带一次）。

| 段落 | 字符 | 每轮出现 | 备注 |
| --- | --- | --- | --- |
| 研判骨架 | 2 543 | 5 | 6 条叙事经济学原理，与 5 分钟级交易决策相关性低 |
| 账户快照 | 1 147 | 5 | 10 只持仓 × 约 110 字符 |
| 指数技术面 | 1 153 | 5 | 5 只指数 × 165 字符 |
| 候选池 | **6 071** | 5 | 35 行 × 173 字符；上限 80 行 ⇒ 约 13.8K 字符 |
| 约束 | 136 | 5 | 活配置只有 30% / 20%，其余「未设置」 |
| 真实账户持仓 | 346 | 5 | 与 ETF 合并、候选池 `[持仓]`、棱镜明细重复 |
| ETF 按产品合并 | 64 | 5 | 无同产品时只有一行「—」 |
| 行业暴露 | 60（失败）/≈450（成功） | 5 | 当前 f127 长期失败 ⇒ 基本恒为一行原因 |
| 行情摘要 | 1 073 | 5 | 43 个 secid × 约 25 字符 |
| 金十快讯 | **4 490** | 1（仅信息面） | 30 条 × 150 字符 |
| **单路合计** | **≈12.7K（非信息面）/ 17.4K（信息面）** | — | |
| **汇总** | ≈22.9K | 1 | 12.7K 上下文 + 10.2K 四路原文 |
| **单轮合计** | **≈78K 字符 ≈ 45–55K token**（0.6–0.7 token/字粗估） | | 48 轮/日 × 5 调 = **240 次 LLM 调用/日** |

**结构性重复**：

- **现价**：`行情摘要` 43 行 / `候选池` 35 行 / `棱镜持仓明细` 10 行，三处大量重叠、三个时间点。
- **持仓**：`真实账户持仓`（qty+cost）/ `ETF 按产品合并`（qty）/ `候选池 [持仓]`（棱镜持仓 + 指标）/ `棱镜持仓明细`（qty+两种成本+市值+权重）——四个「持仓」、两个账户；`ETF 按产品合并`（真实盘）与 `行业暴露`（棱镜盘）两个标题都没写账户名。
- **现金**：`现金：` / `可买额度：`（同值）/ `行业暴露` 的现金行。
- **权重**：快照 `权重` / 行业暴露 `weight` / 候选池无权重 / ETF 合并 `合计权重`（分母是可计价总市值，不含现金）。

**低价值/疑似从未使用的字段**（无 token 级遥测，按「是否有任何后续判定消费」判断）：

| 字段 | 判断依据 |
| --- | --- |
| `PE` / `PB` / `总市值` | 仅出现在候选池；ETF 行通常为 `—`；没有任何规则引用 |
| `60 日动量` / `MA60` | 技术面 prompt 只点名「均线排列、MACD、RSI、量比、位置」 |
| `当日已成交笔数` | 引擎不据此判定；与 `fills` 口径还不同 |
| `limits.singlePct` / `totalPct` | 客户端完全不读；裁剪优先用配置（P1-11） |
| `已归类 x% + 未归类 y% = 100%` | 把现金混进「未归类」，模型无法用 |
| `未成交挂单：N 笔` | 紧接着的 `【待成交挂单】` 已逐条列出 |

## 7. 专题：失败路径

**直接回答**：没有把缺值写成 0（这点做对了，tech/candidates/quotes 都是 `—（原因）`）；但「—」有 4 种不可区分的情形（停牌 / 代码无效 / 取数失败 / 确实没有），且单路失败、解析失败、取数失败都**不会让整轮报错**。

| 场景 | 现在的行为 | 模型/用户看到什么 | 风险 |
| --- | --- | --- | --- |
| 单路 LLM 失败 | 该路 `text=null, error=…`；`usable` 排除 | 汇总的 `【四路结论】` 只有 2–3 段，**没有「缺一路」标记** | 汇总不知道少了一路，仍按「四路共振」措辞 |
| 单路 LLM 截断 | `streamText` 返回 `text` + `error` 并存 | 被当成 `usable`，整段进 digest | 半截结论被当完整结论 |
| 四路全失败 | `summaryError='四路分析都没有产出 ⇒ 汇总跳过'`，`decision=null` | 路由仍返回 `ok:true`；`placement={0,0,[]}` | 与「模型没动作」不可区分 |
| 汇总 LLM 失败 | `summary=null`、`error` 有值、`decision=null` | `ok:true`、0 笔 | 同上 |
| JSON 解析失败 | 造一个 `limits` 全 null 的 decision，带 `parseError` | `run.error=null`；只有决策流小字里能看到 `parseError` | 0 笔被当「正常不交易」 |
| 候选池取数失败 | 段落只剩「—（本轮取数失败）」 | 强制规则仍说「候选池外一律不下单」 | 当日**结构性禁交易**，且模型可能以为候选池为空 |
| 行情取数失败 | `quotes={}`；快照 `现价 —`，但市值/权重按**摊薄成本**照算 | 数字仍然完整、看起来像真的 | 权重、单票上限判断全部建立在成本上 |
| 行业取数失败 | 暴露整表 `unavailable`（宽基/现金行一起消失）；裁剪侧 `industries={}` | 模型只看到一行原因 | 行业上限静默不生效，无 `clampSkipped` 留痕 |
| 新闻取数失败 | `—（24h 内没有取到新闻）` | 与「确实没有新闻」同文案 | 信息面无法区分「无事件」与「没取到」 |
| 配置缺字段 | `limitsTextOf` 写「未设置」 | 模型被要求「必须等于」这个值 | 只能 null 或自造 |
| 账本不可读 | `assertWritable` 抛 `LedgerUnreadableError` → 400 | 明确错误 | 处理正确（账本降级是既有修复，不属本轮提示词问题） |

## 8. 专题：输出解析

**直接回答**：会。三条路径 —— `orders` 非数组静默 0 笔、单笔非法丢弃后仍按**剩余订单**落库、`side` 非 `sell` 默认 `buy`（HEAD）；`limits` 与 `orders` 不一致时**不校验**，裁剪按「配置 > 模型」选一个执行，落盘仍是模型原值。

`parseDecisionDetailed`（`prismAccount.ts:461-513`）的容错矩阵：

| 模型输出形态 | 解析结果 | 风险 |
| --- | --- | --- |
| 完整 ```json 块 | ✅ 正常 | — |
| 有 fence + 前后散文 | ✅ 取 fence | — |
| 两个 ```json 块 | ⚠️ 取**第一个** | 可能取到示例块而不是决策块 |
| 无 fence + 多个 `{}` | ⚠️ `第一个 {` 到 `最后一个 }` | 跨块切片，通常 parse 失败；偶然也能「成功」 |
| `orders` 缺失 / 不是数组 | ❌ 静默 `[]`，`parseError=null` | 0 笔被当完整决策 |
| 单笔非法（缺 secid / price≤0 / shares≤0） | ❌ 丢弃该笔；`parseError` 只写进 `decision`，第二返回值恒 `null` | 存活的单照常落，整轮不报错 |
| `side: "Sell"` / `"卖"` / 缺失 | ❌ HEAD：一律变 `buy`（工作树已改成丢弃） | **方向反转** |
| `limits.singlePct: 999` / `-5` | ❌ 原样接受（无范围校验） | 自证上限（P0-1） |
| `limits` 缺失 / 字符串 | ⚠️ null | `decisionProblems` 本可发现，但无人调用 |
| `cancel` 里的未知 id | ⚠️ `placeDecision` 静默忽略 | 撤单失败无提示 |
| `shares: "300"` | ✅ `Number` 后取整 | — |
| `shares: 250` | ✅ 解析保留；`clamp` 的 `lot()` 向下取整到 200 | 与模型意图差 50 股，无提示 |

**`limits` 与 `orders` 不一致时**：

1. 解析层**不做任何一致性校验**；
2. 裁剪层按「配置 > 模型」挑一个上限执行（`prismAccount.ts:1448-1449`），但**落盘的 `limits` 仍是模型原值**（工作树已对齐 `singlePct`，HEAD 未修）；
3. 客户端不读 `limits`（`src/client/**` 无引用），所以用户看不到「模型说 20%、引擎按 30% 执行」；
4. 结果：**声明、执行、展示三套口径**，且没有一条告警。建议至少把 `limits` 与 `clampEvents` 的 basis 一起落盘并在决策卡显示。

## 10. 建议统一的口径清单

> 原则：**每个数字只有一个生产者，提示词与引擎都消费同一个对象**；模型只能「读」配置，不能「写」上限。

| # | 口径 | 唯一事实源（建议） | 现状 | 消费方 |
| --- | --- | --- | --- | --- |
| 1 | **总资产 / 总市值** | `accountView.totalAssets`（全持仓实时价，缺价→`null`+原因），一次算出 | 提示词、clamp、暴露、净值点各算一遍 | 快照、clamp、暴露、评估 |
| 2 | **单票权重** | `position.mv / accountView.totalAssets` | 同上，三套分母 | 快照、暴露、clamp |
| 3 | **单票上限** | `settings.perStockPct`；`null` = 无上限且**禁止模型自报补位** | 配置 / 骨架 / 模型三源 | `limitsTextOf`、clamp、决策卡 |
| 4 | **总仓上限** | `settings.maxPosPct`；`null` = 无上限；模型 `totalPct` 只记录不执行 | 只有模型值 | `limitsTextOf`、clamp |
| 5 | **行业上限** | `settings.industryLimits`；模型 `byIndustry` 只回显、不合并 | 模型覆盖配置 | `limitsTextOf`、clamp、暴露 |
| 6 | **行业归属** | `industryDataOf` 一次取数，提示词 / 暴露 / clamp 共用；失败写 `clampSkipped` | 两次取数，失败静默 | 暴露、clamp |
| 7 | **止损成本** | `position.avgCost`；缺失 ⇒ 不判止损 + 原因（**不 fallback 到摊薄成本**） | 缺失时退回摊薄 | 快照、clamp |
| 8 | **摊薄成本** | 仅展示；**禁止进入任何判定** | 已基本做到，但数值可荒谬 | 快照展示 |
| 9 | **可卖数量** | `position.available` 写入快照；clamp 用同一字段 | 快照缺失 | 快照、clamp、撮合 |
| 10 | **可买额度** | `cash − totalAssets × minCashPct − 预估费用`，按整手向下 | 直接等于现金 | 快照 |
| 11 | **日 / 累计回撤** | 只保留 `drawdownGateOf`；阈值（含默认值）显式进提示词；状态进快照 | 两套算法、阈值不可见 | 提示词、clamp、决策卡 |
| 12 | **净值 / 总资产时刻** | 快照 = 最新净值点；两处带同一个 `asOf` | 实时 vs 每日点 | 快照、评估 |
| 13 | **时间上下文** | 每轮注入 `slot / now / 距收盘 / 距上次决策` | 无 | 提示词 |
| 14 | **行情时刻** | 每段行情带 `asOf`；缓存段落标注「截至 HH:MM」 | 无 | 提示词 |
| 15 | **新闻窗口** | 24h 全量摘要，或 `important` 优先 + 「另有 N 条未展示」 | 最新 30 条硬截断，`important` 丢弃 | 信息面 |
| 16 | **候选池 / 自选池** | 统一一个概念；超 80 条给截断说明；不可交易标的单列「不可交易」 | 两套语义 | 提示词、clamp |
