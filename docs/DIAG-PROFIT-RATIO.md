# 诊断：1.601872 盈利比例三值差异（94.47 / 85.95 / 79.77）

**读取时点**：v0.51.0 / HEAD `80082f9`，10-12 09:20–09:40 实测。只诊断，未改 `src/`。全部证据来自插件路由与本机缓存，未裸探第三方。

## 结论（一句）

**三个值不是同一个原因**：`79.77` 与 `85.95` 是**同一份数据、不同输入**（今晨集合竞价 `price=21.51` vs 昨夜 `price=22.07`，且 `floatMv` 随价格联动 173.68G→178.2G）；`94.47` **未归因**（实现者手上的缓存与真宿主不是同一份）。**但底层确有一个真实的口径问题**：磁盘缓存里的 10-09 bar 是**当天盘中 09:33 保存的未完成 bar**（`vol=222846 / close=21.93 / low=21.81`），真宿主内存里是完整 bar（`vol=2115568 / close=22.07 / low=20.65`）—— 谁用磁盘缓存复现，谁就会拿到第三个数。**前复权口径混用也确实存在**（因子 1.02463），量级约 **5.7pp**。

## 精确归因（用生产函数 `chipSeriesOf` 复现）

| 目标值 | 复现输入 | 复现值 | 判定 |
|---|---|---|---|
| **79.77**（真宿主 10-12 09:21） | 真宿主 bars + `price=21.51` + `floatMv=173.68G` | **79.77**（avg 18.9287） | ✅ 精确命中 |
| **85.95**（真宿主 10-11 23:0x） | 真宿主 bars + `price=22.07` + `floatMv=178.2G` | **85.95**（avg 18.8848） | ✅ 精确命中（avg 与记录的 18.88 吻合） |
| 94.47（实现者本地缓存） | 扫 160 组参数（bars 来源 × price 21.51–22.87 × window 45/120/250/360 × decay 1.0/1.5 × floatMv 两种） | 最接近 94.51，但 avg 18.71 ≠ 记录的 18.75 | ❌ **未归因**（见「未确认」） |

## 必查项逐条

**1) 现价取自哪里**：**报价快照**。`src/host/routes.ts:255` `price: quote?.price ?? null`（quote 来自 `em.fetchQuotesWithProvenance([secid])`，`:247`）；而桶价来自 `em.fetchKline(secid, 101, cum, 1)`（`:245`，**fqt=1 前复权**）。同一日期两个结果（真宿主 bars，floatMv=173.68G）：`price=21.51 → 79.77`，`price=22.07 → 85.64`（差 **5.87pp**）。

**2) 最新一根是否计入**：**计入**（`chipSeriesOf` 的 `win = bars.filter(...).slice(-window)`，`src/host/chips.ts:265`；窗口 `CHIPS_WINDOW=360`，`chips.ts:23`）。去掉最新一根的对照（真宿主 bars）：`去最后一根 + price=22.07 → 89.26 / avg 18.795`，`去最后一根 + 21.51 → 83.14 / avg 18.795` —— 与含最后一根相比 **PR +3.5pp、avgCost −0.13 元**，说明 10-09 那根对分布有实质贡献。

**3) ⚠ 前复权口径混用：成立。** 同一根日线的 `fqt=0 / fqt=1` 比值：
```
10-09：close(fqt0)=22.47 / close(fqt1)=21.93 = 1.02463
最近 360 根里 301 天因子 ≠ 1；全序列 maxDev = 0.196（19.6%）
```
⇒ 窗口内确有多次除权，**「未复权现价 vs 前复权桶价」是口径错误**。量级（真宿主 bars，同源对比）：混用 `price=21.51 → 79.77`；同口径 `price=21.51×1.02463=22.04 → ≈85.5`（取 `22.07 → 85.64`）⇒ **该错误使用户看到的 PR 比同口径结果低约 5.7pp**，方向是**低估**（未复权现价低于前复权等价价时）。

**4) 边界与实现细节**：比较用 **`<`**（`chips.ts:352` `centers[idx] < price`）；桶价用**桶中心**（同上，`centers[idx]`）；现价缺失 ⇒ `profitRatio=null`、**avgCost 仍给**（`chips.ts:349-350`，注释 `:225-226` 同）。

**5) 数据来源差异：两份数据确实不同（本次最重要的发现）。** 同一路径 `klines/1.601872_101_1.json`，但：
| 字段 | 磁盘缓存（mtime 10-09 09:33，我读的） | 真宿主内存（`/kline` 回包） |
|---|---|---|
| 10-09 `close` | 21.93 | **22.07** |
| 10-09 `low` | 21.81 | **20.65** |
| 10-09 `vol` | **222,846** | **2,115,568** |
⇒ 磁盘那份是**盘中未完成 bar**，真宿主那份是完整 bar；且真宿主**没有回写磁盘**（第二次 `curl /kline` 后该文件 mtime 仍是 10-09 09:33）。两次真宿主调用（昨夜/今晨）的最新 bar 日期同为 10-09，但 `price` 与 `floatMv` 不同（22.07/178.2G → 21.51/173.68G）。

## 影响面

- **`price` 只影响 `profitRatio`**（实测：同 bars 下改 price，`avgCost/support/resistance` 逐位不变）⇒ 79.77/85.95 的差**不是**口径错误。
- **前复权混用也只影响 `profitRatio`**（avgCost/support/resistance 只用桶价，不碰现价）⇒ 量级 5.7pp。
- **磁盘缓存 vs 真宿主内存（未完成 bar）影响全部四个数**：`avgCost 18.8082 vs 18.9287`、`support 14.7094 vs 14.7407`、`resistance 22.1581 vs 22.1483`、`profitRatio 82.79 vs 79.77`（同为 price=21.51）⇒ 这条是"94.47 与另两值不可比"的结构性原因。

## 修正方向（不实现，供决策）

1. **前复权混用**：`profitRatio` 的现价换算到与前复权序列同口径（`price × close(fqt1)[-1] ÷ close(fqt0)[-1]`），或整段改用 `fqt=0` 序列 + 未复权现价；二选一并写进 `methodology`（现在 methodology 只写了"窗口 fqt=1"，没写现价口径）。
2. **未完成 bar**：kline 缓存在盘中写盘会把"正在走的 bar"固化进磁盘（本次证据：10-09 09:33 写盘、vol 只有全天 10.5%），后续读盘方（含筹码）会拿到缩水分布。建议在实现批次评估"盘中不落盘 / 或落盘时标记 `barOpen` 并在读时回源补齐"。
3. **诊断可比性**：报告三方数值时应同时给出 `bars 来源（磁盘/内存）+ 最新 bar 的 date/close/vol + price + floatMv`，否则数值不可比（本次就是这样丢失了 94.47 的上下文）。

## 未确认

1. **94.47 未归因**：160 组参数扫描里最接近的是 `disk bars + price 22.07 + window 120 + decay 1.0`（PR 94.51，但 avg 18.71 ≠ 记录的 18.75）；也可能是实现者机器上的另一份 bars（例如 10-09 `vol` 介于 222846 与 2115568 之间）。**确认方法**：请实现者提供当时那份 `klines/1.601872_101_1.json` 的 `updatedAt`、10-09 bar 的 `{close, low, vol}`，以及调用参数（window/decay/spread/floatMv）。
2. 「同口径」只验证了"前复权 bars + 前复权等价价"这一条路径；"不复权 bars + 不复权现价"的等价路径未算（缺当时点的 `fqt=0` 全窗 bars）。
3. 券商 96.87%（现价 22.07）与本模型 85.95 的差（约 11pp）未追：需知道券商用的窗口/衰减口径，本仓库无此数据。
