# 设计稿：棱镜模拟盘「自动做T」（可开关）

> 状态：**仅设计，未实现**。本文不修改任何 `src/**`；界面原型见 `docs/prototype/prism-autot.html`。

## 0. 一句话

对**标记为中长期持有**的持仓，每天由智能体给出一个「日内正T / 反T」计划（价位 + 股数 + 最晚回补时间），
由引擎按确定性规则盯盘执行；**净持仓不变**，T 的价差收益单独记账，用于降低「有效成本」。

## 1. 目标与非目标

| 目标 | 非目标 |
| --- | --- |
| 在不改变底仓数量的前提下，赚取日内波动价差 | 不做择时加仓/减仓（净持仓必须回到计划前） |
| 每只标的可单独开关，全局总开关默认关闭 | 不替代现有决策流（做T是独立通道，不占 `decision.orders`） |
| 收益可对账：每轮 T 的买/卖、费用、价差单独留痕 | 不承诺降成本；价差不足或行情单边时当轮不做 |
| 与 T+1、止损线、单票上限、回撤闸门全部联动 | 不在停牌/涨跌停/新股的标的上做T |

## 2. 名词与 A 股约束（决定能不能做）

| 名词 | 含义 | 关键约束 |
| --- | --- | --- |
| **正T** | 先买后卖：低位买入 N 股，再卖出**底仓**中 N 股（当日买入不可卖，卖的是旧仓） | 需要现金 ≥ N×买价；底仓 `available` ≥ N |
| **反T** | 先卖后买：高位卖出底仓 N 股，再买回 N 股 | 需要 `available` ≥ N；买回资金来自卖出款 |
| 单轮规模 N | 每次 T 的股数 | `N ≤ min(available, floor(qty × maxPctPerRound))`，且为 100 股整手 |
| 净持仓 | 收盘时 `qty` 必须等于开盘时 | 未回补 ⇒ 强制在 14:55 前回补，否则记为「T 失败」并还原 |
| 费用 | 佣金（双边，最低 5 元）+ 印花税（卖出 0.05%）+ 过户费/滑点 | 价差必须先覆盖费用，否则不触发 |

> **禁止**用「当日买入的股份」去卖（T+1）；正T 的卖出腿只动 `available`，引擎必须校验。

## 3. 状态机

```
OFF ──开启总开关──▶ ARMED（等待当日计划）
ARMED ──08:55 生成计划──▶ PLANNED（挂着条件，等触发）
PLANNED ──触发买入/卖出腿──▶ EXECUTING（一半已成交，等另一半）
EXECUTING ──两腿完成──▶ DONE（结算：收益入账，留痕）
PLANNED/EXECUTING ──14:50 未完成 / 触发风控──▶ ABORTED（撤单 + 必要时回补）
任意状态 ──关闭开关 / 账本 degraded──▶ OFF（撤销所有未成交 T 单）
```

一天一只标的**最多 1 轮**（默认；可配 2），无论成功失败，当日不再发起。

## 4. 决策链路（谁在什么时候做什么）

| 时点 | 角色 | 动作 |
| --- | --- | --- |
| 08:55 | 智能体（每标的独立小请求，或汇总统一规划） | 读：持仓、`avgCost`、`available`、现金、ATR(14)、20 日高低、MA20、行业/新闻；产出 **T 计划 JSON**：`{secid, direction:'buy-first'|'sell-first', buyPrice, sellPrice, shares, deadline, reason, invalidateIf}` |
| 09:25 | 引擎（确定性） | 校验 12 条（见 §5）；通过则挂两张**条件单**（一张触发、一张反向），不通过则退回并记录原因 |
| 09:30–14:50 | 引擎（每 1 分钟） | 监控触发价；成交一腿后立即挂另一腿；写 `tTrades` |
| 14:50 | 引擎 | 未完成 ⇒ 撤销剩余条件单；若已成交一腿 ⇒ 按市价回补（标记 `forced`） |
| 15:05 | 引擎 | 结算：算净收益（含双边费用），写当日 `tResult`；更新「有效成本」展示值 |

**为什么不让 LLM 每分钟决策**：成本高、延迟大、易漂移。LLM 只定「今天的计划」，执行交给确定性引擎。

## 5. 引擎校验清单（全部通过才挂单）

1. 全局开关 + 该标的开关均开；
2. 该标的 `autoTHold === true`（中长期持有标记）；
3. 当日轮次 < `maxRoundsPerDay`；
4. `shares % 100 === 0` 且 `shares ≤ min(available, floor(qty × maxPctPerRound))`；
5. 正T：`cash ≥ shares × buyPrice`；反T：`available ≥ shares`；
6. 价差 `(sellPrice / buyPrice − 1) × 100 ≥ minSpreadPct`（默认 0.8%，且 ≥ 2×预估费用率）；
7. 买价/卖价在当日涨跌停区间内，且不是停牌/一字板；
8. 计划价与现价偏离 ≤ 3%（复用现有偏离闸）；
9. 回撤闸门未触发（触发时暂停自动做T，避免与降暴露冲突）；
10. 该标的未触及 −20% 止损（用 `avgCost`）；
11. 当日无同标的未完成的 T 单；
12. 账本未 degraded。

## 6. 成本口径（重要，避免破坏现有账务）

现有账本已改为**账面成本法**：`cost` = 买入均价，卖出不改成本，盈亏进 `realized`。
因此做T**不直接改 `cost`**，而是：

- 新增 `tProfitPool`（累计做T净收益，含费用），持久化；
- 展示层派生：`有效成本 = cost − tProfitPool / qty`（仅当 qty > 0）；
- 详情页同时显示「账面成本 / 做T累计 / 有效成本」三个数，避免把做T收益重复计进 `realized`。

> 若把 T 收益再写进 `realized`，会与 `tProfitPool` 重复；设计上 **`tProfitPool` 单列**，绩效卡展示「做T收益」独立指标。

## 7. 参数与默认值

| 参数 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `autoT.enabled` | **false** | — | 总开关，默认关闭 |
| `autoT.maxRoundsPerDay` | 1 | 1–3 | 每标的每日最多轮次 |
| `autoT.maxPctPerRound` | 20% | 5–50% | 单轮最多动底仓比例 |
| `autoT.minSpreadPct` | 0.8% | 0.3–3% | 触发所需最小价差 |
| `autoT.deadline` | 14:50 | — | 最晚完成时间 |
| `autoT.onlyHoldDays` | ≥5 | — | 持有不足 5 天不做T |
| 每标的 `autoT` | 关 | — | 逐只 opt-in |

## 8. 数据模型（建议）

```ts
// settings 增量
autoT?: {
  enabled: boolean
  maxRoundsPerDay: number
  maxPctPerRound: number
  minSpreadPct: number
  deadline: string        // 'HH:MM'
  positions: Record<string, { enabled: boolean; hold: boolean }>
}

// 新账本 prism-autot.json（与三账本分开，失败不影响主账）
{
  v: 1,
  plans: PrismTPlan[],      // 当日计划（含 invalidateIf）
  trades: PrismTTrade[],    // 每腿成交：planId, secid, side, shares, price, fee, at, forced
  results: PrismTResult[],  // 每轮结算：buyPrice, sellPrice, shares, gross, fees, net, day, secid
  profitPool: Record<string, number>  // secid → 累计净收益
}
```

## 9. 提示词增量（给智能体）

```
【自动做T·计划】只对开启做T的中长期持仓生成计划，其余一律 output null。
输出 JSON：{secid, direction, buyPrice, sellPrice, shares, deadline, reason, invalidateIf}
硬约束：
- 净持仓必须不变；shares 只能是 100 的整数倍，且 ≤ 可卖数量与单轮上限。
- 价差必须先覆盖双边费用（默认 ≥0.8%）；覆盖不了就 output null。
- 触发止损（按买入均价）或回撤闸门开启时，output null。
- 只给计划，不下单；执行由引擎完成。
```

## 10. 界面结构（见 HTML 原型）

1. **总开关卡**：开关 + 今日轮次 + 今日/累计做T收益 + 有效成本降幅；
2. **参数行**：单轮上限 / 最小价差 / 每日轮次 / 最晚回补；
3. **持仓表**：底仓、可卖、账面成本、有效成本、今日计划、状态、逐只开关；
4. **计划详情**：方向、买/卖价、股数、预计收益（扣费）、失效条件；
5. **今日流水**：时间轴（计划 → 买腿 → 卖腿 → 结算 / 失败回补）；
6. **空态**：`—` + 一句原因（缺 ATR / 持有不足 5 天 / 关闭状态）。

## 11. 异常与降级

| 场景 | 处理 |
| --- | --- |
| 行情断流 | 不触发；计划标记 `stale`；14:50 强制回补 |
| 涨跌停/停牌 | 不挂单；当日跳过并留痕 |
| 只成交一腿且无法回补（跌停） | 记 `forced-fail`，净持仓偏离；次日开盘优先回补并告警 |
| 账本 degraded | 总开关自动置 OFF，撤销所有未成交 T 单 |
| 用户手动平仓该标的 | 撤销其 T 计划与未成交单 |

## 12. 观测与验收

| 指标 | 定义 |
| --- | --- |
| 做T胜率 | `net > 0` 的轮次 / 完成轮次 |
| 平均单轮净收益 | Σnet / 完成轮次 |
| 成本下降 | `tProfitPool / 当前市值`（年化另算） |
| 未回补次数 | `forced` + `forced-fail` 计数（必须为 0 才可扩大规模） |
| 费用占比 | 双边费用 / 毛价差 |

**验收门槛（建议）**：纸面运行 20 个交易日、完成轮次 ≥ 15、未回补 0 次、平均净收益 > 0，才允许把单轮上限从 20% 提到 30%。

## 13. 分阶段上线

1. **影子模式**：只生成计划、不挂单，记录「如果执行会怎样」；
2. **单票试点**：只对 1 只流动性最好的持仓开启，单轮 10%；
3. **多票**：最多 3 只，单轮 20%；
4. **全量**：按验收指标决定是否放开。

## 14. 风险清单

- **T+1 误用**：正T 的卖出腿若用了当日买入的股份 ⇒ 直接拒单；引擎必须用 `available` 判定。
- **手续费吃掉价差**：低价 ETF 双边最低 5 元佣金，500 份 × 0.8% ≈ 0.4 元价差 ⇒ 不够费用；`minSpreadPct` 必须按「费用/名义金额」动态抬升。
- **单边行情**：反T 卖出后股价继续涨 ⇒ 回补亏损；用 `invalidateIf`（如突破当日高点 1%）+ 单轮亏损上限（建议 −0.6%）止损回补。
- **与主决策冲突**：主决策要减仓时，先撤销该标的 T 计划，再执行减仓。
- **数据造假风险**：T 收益必须来自真实成交（`fills`），不得用计划价估算。
