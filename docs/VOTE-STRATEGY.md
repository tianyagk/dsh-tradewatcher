# 策略复核投票（PM-BACKLOG-PRISM / RESEARCH-STRATEGY）

> 只读复核。对象：`docs/PM-BACKLOG-PRISM.md`、`docs/RESEARCH-STRATEGY.md`、当前 `src/host/prismPipeline.ts` / `src/shared/prism.ts`。
> 立场：决策管线与防洗白；不新增数据源。

## 一行结论

首批 5 项全部方向正确；P-04 与 P-10 需附加可验证条件，P-08 必须坚持“只裁不新建、缺数不夹紧”；决策层的优先级应先要可证伪条件，而不是先造一个可能被模型自证自洽的证据 schema。

## 1. P 项投票（5/5）

| 项 | 票 | 一句理由 |
| --- | --- | --- |
| **P-01** 权益口径与现金流分离 | **同意** | 入金被记成上涨是当前唯一已被实测证伪的数字，且 S 级只加字段、不改旧点。 |
| **P-04** `code_version` + `mandate_hash` | **有条件** | `mandate_hash` 复用 checksum 值得做；手维护的 `code_version` 必须有构建断言/变更记录，否则只是一个会过期的标签。 |
| **P-05** 量能约束 + 无量源降级 | **同意** | 成交量字段本来就在回包但被 map 丢弃，拒绝 `trend` 无 volume 的“必成交”比现状诚实。 |
| **P-08** 仓位上限真正执行 | **同意** | 上限只记录不执行是五份报告的共同盲区；只做确定性裁剪、不新建委托，缺数据不夹紧。 |
| **P-10** 持仓行业暴露表 | **有条件** | 行业暴露是首个可核对的新诚实数字，但必须标“未穿透/行业缺失”，不得用 ETF 名称猜行业。 |

## 2. C-1…C-6 选边（6/6，不弃权）

| 分歧 | 选边 | 一句理由 |
| --- | --- | --- |
| **C-1** 决策层第一件事：引用契约 vs thesis | **乙：先 P-15 thesis** | 可证伪条件不依赖额外 LLM 调用或证据 ID，先把“什么情况下我错了”变成必填，能立刻抑制事后叙事；P-13 紧随。 |
| **C-2** 先修权益口径 vs 先修评估口径 | **固收：先 P-01** | P-03 的回撤直接依赖 P-01；P-02 无依赖，可同日并行，不必把 P-03 提前。 |
| **C-3** 行业上限是否等 `singlePct` | **甲：与 P-08 同一条提交** | 没有裁剪器的行业上限只是第二个“只记录”；但 P-11 排 P-08 之后，不抢首批位置。 |
| **C-4** 红队值不值一次额外调用 | **暂缓 P-18** | 先让 P-12/P-13 对已有四份报告做零额外调用的事后审计；同模型红队的反证质量未经验证，先加只会多一段散文。 |
| **C-5** 降仓由谁执行 | **固收（阈值触发），但只提示 + 拒新买单** | 阈值必须有执行后果，但引擎自动卖出会变成模型之外的第二决策者；行业集中度只能作为解释，不拥有触发权。 |
| **C-6** 滑点先常数还是先冲击 | **量化：先 P-05 量能，再做参与率平方冲击并版本化** | 常数与冲击是同一字段的两种算法，分两批等于改两次；没有 volume 时冲击项没有意义。 |

## 3. 先做会踩的坑（3 条）

1. **先加 evidence 字段、后做证据抽取 ⇒ gate 只能“自证自洽”。** 四路现在只产自由文本（`prismPipeline.ts:105-116`），digest 只是拼接（`:123`），parser 只挑已知字段（`prismAccount.ts:258-299`）。若先让模型自己写 `evidence[]`，P-13 只能校验“ID 是否存在”，无法阻止模型把结论改写成证据。**先把现有输入行确定性生成 ID，再做 shadow；否则只是换一种洗白格式。**
2. **P-05 把 `trend` 的无 volume 当成 0 直接拒绝 ⇒ 盘中兜底源全部不成交。** `trend` 的 bar 用 `high=low=price`（`prismAccount.ts:505-508`），撮合也只看价格、不看 volume（`:123-140`）。必须区分 `volume=null`（未知，拒绝并说明）与 `volume=0`（零成交），否则用户会看到“有行情但永远不成交”。
3. **P-08 先裁剪、却用未修好的权益/现金口径做分母 ⇒ 夹紧结果不可信。** 现在仅检查 `limits` 非空（`prismPipeline.ts:49`），下单路径在 `prismAccount.ts:551-620` 只做静态约束；若 P-01 的 `capital` / 现金流未先落地，单票/总仓上限会被“含入金的权益”放大，裁剪反而制造新的错误数。先 P-01，再 P-08 的 enforce。

## 4. 边界

- **不改代码、不跑测试**；本文只投票。
- P-04 的 `code_version` 若不能做到构建时自动校验，就降级为“有条件未满足”，不要先上线一个手填常量。
- P-10 的“未穿透”不是免责声明，而是数据列：缺失就写 `—` + 原因，不猜行业、不把 ETF 名称当成分股。
