## 0. 裁决（先给结论）

| # | 裁决 | 一句话理由 |
| --- | --- | --- |
| **D1** | **因子层只服务「自动做T 的可执行性门槛」**：不选股、不评分、不排序、不进四路分析、不进主决策下单。 | 主决策已有 LLM + 行业暴露 + 回撤闸门；再加一层因子观点只会增加 token 与同质化，不会让单子更对。 |
| **D2** | **因子层不是审计修复的替代品**：44 条审计项里**直接解决 0 条**，部分改善 3 条（#13 / #24 / UI P1-5 文案），另有 1 处会加重风险（#20 文件膨胀）。**12 条宿主项仍开放**，其中 #10/#11/#16 是 P1。 | 因子层解决的是「为什么没做、门槛是否可信」；审计里绝大多数是「净持仓、账本、生命周期」——两件事。 |
| **D3** | **第一期 0 大改**：只在自动做T 弹窗做 3 处字段级文案（不新增按钮/卡片/列/面板），按用户规则由产品经理决断，**不需要 HTML 原型**。 | 3 处都是替换已有文本，布局变化为 0；见 §3.3。 |
| **D4** | **因子日志只落盘；影子 A/B 只落盘 + 20 轮后出报告；两者永不进主界面**。 | 日志是排障资产，不是日频信息；影子收益进 UI 必然被读成「另一套更赚的策略」。 |
| **D5** | **5 个 chip 不变，不加第 6 个**；「做T N 次」等表格汇总口径不变。 | chips 是唯一汇总口径；因子是标的级条件，不是汇总指标。加「门槛通过数」会与「今日轮次」打架（通过 ≠ 做了）。 |

**一句话结论**：因子层值得做，但只值得做「**一条可核对的拒绝理由**」；做完之后用户应当能回答「今天这只为什么没做T、差多少」，而不是看到一张因子表。**在 #10/#11/#16/#24 关闭之前，不要对外宣称自动做T 已优化完成。**

## 1. 需求范围：哪些进 UI，哪些只做后台

### 1.1 现状与问题（为什么不是「再加一个面板」）

| 现状 | 证据（v0.249.0） | 用户后果 |
| --- | --- | --- |
| 「适不适合做T」只写在提示词里：ATR14/现价 ≥1.5%、20 日振幅 ≥3% | `prismPipeline.ts:189` | 模型可以忽略；没有任何代码拒绝；事后无法核对是否达标 |
| ATR14 / 20 日振幅已经算好并喂给模型 | `prismRoutes.ts:365-389`（v0.249.0） | 数有了，但**没有判定、没有留痕、界面看不到** |
| 引擎真正的硬门槛散落在三处：20% 底仓、1.2% 价差、扣费后净额 ≥ max(20 元, 0.3%) | `prismRoutes.ts:678/681/683/688` | 被拒时 `continue` 静默跳过：不写计划、不写原因、UI 无痕 |
| UI 对「没有计划」给的是猜测式并列原因 | `prismDeskSide.ts:609-618`：`今日无计划` + title「价差不足/风控/数据缺失」 | 用户不知道到底是哪一条；这是「三选一猜谜」，不是解释 |
| 毛价差与净额不同口径 | `prismDeskSide.ts:636-640` 只算 `sell/buy−1`；计划卡写「价差（扣费前）」 | 看到 +1.83% 以为赚，实际扣费后可能只剩 96.20 元甚至被拒 |

结论：**因子层的第一价值是「把已经存在的判定变成可见、可核对、可留痕的事实」，不是新增因子。**

### 1.2 四个能力的产品定义

| 能力 | 定义（产品口径） | 不是什么 |
| --- | --- | --- |
| **因子快照** | 每标的每日一份、**只用到昨日收盘为止的日K**（剔除当日未完成 bar）的 2 个因子：`ATR14%`、`20日振幅%`，加 `bars`（可用根数）与 `asof`（数据截至日）。 | 不是盘中实时因子；不是多因子库；不含 MA/RSI/量比等未设门槛的指标。 |
| **确定性门槛** | 引擎在挂单前按固定常量判定「能不能做」，产出**唯一的第一阻断原因**；门槛是必要条件，不是充分条件。 | 不是评分、不是排序、不是买卖信号；不改 LLM 的选价/选方向。 |
| **因子日志** | 每次研判对每只开启做T 的持仓写一行：因子值 + 门槛版本 + 判定 + 影子判定。日分片、30 天保留。 | 不是用户可见报表；不是第二套账本；不参与成交与结算。 |
| **影子 A/B** | 同一份快照上，用 B 门槛（单一变量）再判一次，只记录「B 会不会挡」，**不挂单、不调用 LLM**；≥20 个完成轮后才出描述性报告。 | 不是模拟交易；不是收益预测；不自动切换门槛。 |

### 1.3 必须进 UI 的（只有三项）

| # | 能力 | 展示位置 | 字段 / 文案 | 为什么必须进 |
| --- | --- | --- | --- | --- |
| **U1** | 门槛结论 | 自动做T 弹窗 · 持仓表第 5 列（原「Agent 今日判断」→ 表头改「今日计划 / 门槛」） | 无计划时：`条件不足 · ATR 1.12% < 1.50%` / `条件满足 · Agent 未给计划` / `—（日K未取到：超时）` / `已过截止 14:50` / `已达 2 轮上限` / `风控冻结 · 回撤闸门` | 这是用户每天唯一会问的问题：**为什么没做**。没有它，开关打开后一片空白 |
| **U2** | 扣费后净额 | 弹窗左面板 meta 第 3 格：标签「价差 / 扣费后净额」 | `+1.83% / +96.20`；缺值 `+1.83% / —` + title 原因 | 现有「价差（扣费前）」与引擎实际用的净额门槛不同口径，是口径撒谎 |
| **U3** | 无计划空态 | 左面板「Agent 判断」空态 | `—（今日无计划：3 只条件不足，1 只未给计划）` | 把黑箱变成可数的分布；否则用户只能逐行看表 |

> **U1 的 title（悬停全文）**：`ATR14 1.12% < 1.50% · 20日振幅 3.42% ≥ 3.00% · 日K 30 根（截至 2026-11-25 收盘）· 门槛 t-gate-v1`。
> 移动端没有 hover，所以 **U1 的主文案必须自足**（含数值与门槛），title 只是补充。

### 1.4 只做后台、不展示的

| 能力 | 落点 | 为什么不展示 |
| --- | --- | --- |
| 完整因子快照（逐标的 JSON） | `prism-factor/<day>.jsonl` | 2 个因子 + 元数据已足够解释；全量展示会诱发「自己看因子择时」 |
| 因子日志（逐轮逐标的） | 同上，30 天保留 | 日频看无价值；只在排障/复盘时读 |
| 影子 A/B 判定与报告 | 日志字段 + `scripts/verify-prism.mjs --factors` 输出 | 样本 <20 时展示即误导；≥20 后也只写「过去 N 轮发生了什么」 |
| 门槛版本变更记录 | `T_GATE_VERSION` 常量 + CHANGELOG | 版本进 title 即可，不需要界面 |
| 被拒计划的原始买/卖价 | 日志 `kind:"plan"` 行 | 展示会变成「马后炮价格」，诱导「要是当时挂了就赚了」 |

### 1.5 明确不做的（本期与可见未来）

| 不做 | 理由 |
| --- | --- |
| 第 6 个 chip「今日可做 N 只」 | 通过 ≠ 做了；与「今日轮次」语义打架；`<560` 的 2×3 chip 布局会破 |
| 决策流「做T」tab 增加「未通过门槛」分组 | 未通过门槛不是委托，混进委托流会伪造「有一笔单被拒」的观感；弹窗已能回答 |
| 因子评分 / 星级 / 置信度 / 因子排名 | 与 R10 冲突（不得表述为有预测能力）；且会诱导按分数做T |
| 因子进四路分析或主决策 | 见 D1；先解决 §6.2 的重复注入问题 |
| 用户可调门槛（settings） | 没有样本就调参 = 过拟合；且需要新设置 UI（大改） |
| 因子回测引擎 / 机器学习 | 免费源无历史分单/逐笔，回测口径不可信；本期只做「同日同快照的影子对照」 |
| 因子页 / 新 tab / 新抽屉 | 单标的 2 个因子撑不起一个页面 |

## 3. UI 改动分级

### 3.1 分级标准（把用户规则落成可判定条款）

| 级别 | 判定 | 流程 |
| --- | --- | --- |
| **无改动** | 只动宿主/数据/日志/提示词，用户看不到任何像素变化 | 工程自测 + 本文验收 |
| **小改** | 只替换已有文本/字段/表头/单个按钮；不新增行、列、卡片、面板、页；布局盒尺寸变化 ≤ 1 行 | **产品经理决断**，本 PRD 即决策记录，不需 HTML |
| **大改** | 新增面板/页/tab/列/卡片组，或改变弹窗高度分配、滚动结构、信息层级 | **必须先出 HTML 原型给用户审核**，审核通过才实现 |

### 3.3 小改规格（可直接施工）

#### U1 持仓表第 5 列

```
表头：  今日计划 / 门槛
列宽：  21%（不变；≤860 时 30%，≤560 时 29%，均不变）

有活跃计划：  [正T] 1.236 ↔ 1.248 · 1,000 股          ← 现有渲染不动
条件不足：    条件不足 · ATR 1.12% < 1.50%             ← muted
门槛通过但模型没给： 条件满足 · Agent 未给计划          ← muted
数据缺失：    —（日K未取到：超时 8s）                  ← muted
被风控/时间/轮次挡： 风控冻结 · 回撤闸门 / 已过截止 14:50 / 已达 2 轮上限
开关关闭：    未开启做T                                 ← 现有文案不动
```

- `≥861px`：`white-space:nowrap; text-overflow:ellipsis`，**只占 1 行**（当前 judge 列是 `white-space:normal`，计划文本本来就 1 行；改后仍 1 行）。完整句进 `title`。
- `≤860px`：允许 2 行换行；`≤560px` 同。
- 文案硬上限 **22 个全角字符**（按 12px 字体、186px 列宽实测）。超出时**截断的是尾部**，所以数值+门槛必须排在前面：`条件不足 · ATR 1.12% < 1.50%`，不要写成 `ATR 低于门槛，当前 1.12%`。
- 不加图标、不加颜色语义：`条件不足` 用 `--tw-muted`，不用红/绿（门槛不是涨跌）。

#### U2 左面板 meta 第 3 格

```
标签：价差 / 扣费后净额
值：  +1.83% / +96.20
缺值：+1.83% / —        title：旧计划未落扣费后净额（t-gate-v1 之前）
无计划：— / —           title：今日无做T计划
```

- 仍为 3 格网格（`repeat(3,1fr)`），**不新增第 4 格**；`≤560px` 仍为单列 3 行。
- 数值一律 `signedPctOf(v,2)` + `signedMoneyOf(v,2)`；净额是**计划值**，title 必须写「按计划价与双边费用估算，未成交」。
- 若计划股数被 20% 底仓裁剪，净额按**裁剪后股数**算（与引擎门槛同一口径）。

#### U3 左面板空态

```
无任何计划：
  —（今日无计划：3 只条件不足，1 只未给计划）
  title：条件不足明细见持仓表；「未给计划」= 门槛已通过但 Agent 本轮没有给出
无开启标的：
  —（自动做T 未启用）        ← 现有
今日研判未运行：
  —（今日尚未研判，门槛未计算）
```

- 计数只数**开启做T 且有持仓**的标的；不要用全部持仓做分母。
- 0 只条件不足时不要写「0 只」，直接省略该分句：`—（今日无计划：Agent 未给计划）`。

## 4. 产品验收标准

### 4.1 用户能看懂什么（验收 5 条）

| # | 用户在一眼内应能回答 | 验收方式 |
| --- | --- | --- |
| **A1** | 今天这只**能不能做T**、如果不能，**第一条原因是什么**（带具体数值与门槛） | 11 行持仓表逐行可读；每行原因 ≤22 字、1 行、自足 |
| **A2** | 「引擎条件不足」「引擎通过但 Agent 没给」「数据没取到」「风控/时间/轮次挡住」是**四件不同的事** | 四种文案互不相似；不出现「今日无计划」+ 三选一 title |
| **A3** | 已挂计划的**扣费后净额**是多少（不是毛价差） | 左面板 `+1.83% / +96.20`；title 写明「计划值，未成交」 |
| **A4** | 这个结论**用的是哪版门槛、哪天的数据** | 任意门槛 title 含 `t-gate-v1` 与 `截至 YYYY-MM-DD 收盘`；旧计划保留旧版本 |
| **A5** | 哪些字是**引擎判的**、哪些是 **Agent 说的** | 表格列头「今日计划 / 门槛」；门槛文案以「条件…」开头；Agent 文案保留 `[正T]` 徽标 |

### 4.2 不能出现什么（红线 11 条）

| # | 禁止 | 反例 | 正确 |
| --- | --- | --- | --- |
| **N1** | 缺失写 0 | `做T 0 次` / `胜率 0%` / `ATR 0.00%` | `—（n=0）` / `—（日K不足）` |
| **N2** | 免责声明 | 「仅供参考」「不构成投资建议」「风险自担」 | 只写口径与原因（R4） |
| **N3** | 评分/星级/置信度/因子排名 | 「因子强度 82 分」「AI 置信度 0.71」 | 只写「通过/不足 + 数值 + 门槛」 |
| **N4** | 预测性表述 | 「预计收益 +96 元」「大概率成功」 | 「按计划价扣费后净额 +96.20（计划值，未成交）」 |

| **N10** | 用红/绿表达门槛通过与否 | 绿色=可做、红色=不可做 | muted 文本；涨跌色只用于盈亏 |

### 4.3 文案与数字口径

| 类型 | 格式 | 示例 | 缺数 |
| --- | --- | --- | --- |
| 金额 | 带符号 2 位千分位 | `+96.20` / `−12.30` | `—` |
| 价差/净额百分比 | 带符号 2 位 | `+1.83%` | `—` |

## 5. 优先级与分期

### 5.1 P0（信任底座，先于或同批于 P1）

见 §2.5：**#10 / #11 / #16 / #24 / #20**。合计约 2.25 人日，全部无 UI 改动。
**完成前不得对外说「自动做T 优化完成」**，也不得把因子层的「条件满足」当成「系统可靠」的证据。

### 5.2 P1（最小可用，约 3 人日）

**范围（只做这些）**：

1. `T_GATE_VERSION = 't-gate-v1'` + 常量表（附录 A）。
2. 因子快照：每日首轮计算，剔除当日未完成 bar；按 secid 缓存；落 `prism-factor/<day>.jsonl`。
3. 门槛 `gateOf()`：G1 数据充分、G2 波动适配、G3 扣费后净额、G4 风控/时间/轮次；输出唯一原因码（附录 B）。
4. `placeAutoTPairs` 用 `gateOf()` 取代 prompt 里的 ATR 规则；被拒计划写 `kind:"plan"` 日志。
5. payload：`positions[].gate` + plan `netEst/gateVersion/factor`。
6. UI：U1/U2/U3 三处文案（§3.3）。
7. 影子：每条 factor 日志带 `shadow` 判定（只记录，不出报告）。
8. 上下文：autoT 段从四路 `compileInput` 挪到汇总调用；提示词删掉「ATR≥1.5%/振幅≥3%」的规则，改为「引擎已过滤」。
9. 测试 E1–E8。

**完成定义（DoD）**：

- [ ] T1–T12 全过，且截图/像素断言留档。
- [ ] 4 路分析文本里 0 次出现 `ATR` 或 `20日振幅`（prompt 层断言，E3）。
- [ ] 11 只持仓的真实数据下，每只都有且只有一个原因码；无 `unknown` 静默。
- [ ] 30 天日志可回读，坏行不影响启动。
- [ ] 1024×768 / 1280×800 / 1440×900 body 无滚动。
- [ ] `npm run check` 全绿；新增测试 ≥15 条。

**P1 明确不做**：因子明细面板、决策流分组、第 6 个 chip、影子报告、阈值可调、主决策接入。

| **门槛 v2 评估** | 影子报告显示某一门槛长期挡住高收益轮次，且 n≥20 | 0.5 人日 + 版本号 |
| X2 ≤860 结果列 | 独立于因子；用户报窄屏看不到金额 | 0.5 人日 |
| X3 胜率 2 位统一 | 独立；仅当有人并排读错 | 0.25 人日 |

> P2 的每一项都必须重新走 §3.1 分级；B1/B2 属大改，先 HTML。

### 5.4 永久不做

## 6. 风险

### 6.1 四角色同质化（最高风险）

**机制**：`prismPipeline.ts:97` 把 `inputs.autoT` 放进 `compileInput`，而 4 路分析（技术面/外盘/大宗/信息面）+ 汇总都用它 ⇒ 同一组持仓/ATR 数字**重复 5 份**。因子层再加内容，会让四路都引用同一组数字，输出趋同，辩论价值归零。

**证据**：`prismPipeline.ts:86-97`（`contextAll`/`contextNoNews` 都来自 `compileInput`）；`prismRoutes.ts:444` 把 autoT 注入 inputs。

**缓解（P1 必做）**：

1. autoT 段只进**汇总/决策**调用，不进 4 路分析。
2. 4 路 prompt 不出现任何因子数值；因子只以「门槛结论」形式进汇总。
3. 不新增「量化因子分析」角色。
4. 提示词明确：`不要在四路分析里复述 ATR/振幅`。

**可测门槛**：E3 断言 4 路 context 不含 `【自动做T`；上线后抽查 4 路文本，`ATR` 出现次数 = 0。

### 6.2 token 成本

**基线**：单轮约 78K 字符（≈45–55K token，AUDIT-PRISM-PROMPT P2-1）。当前 autoT 段约 700 字符 × 5 份 ≈ 3.5K 字符。

**因子层的账**：

| 项 | 变化 |
| --- | --- |
| autoT 段从 5 份降到 1 份 | −2.8K 字符 |
| 通过门槛的标的才进上下文（假设 11 只→4 只） | 每人约 65→85 字符，净 −0.4K |
| 提示词删掉 ATR/振幅规则，改为「引擎已过滤」 | −0.2K |
| 新增门槛结论行（汇总） | +0.2K |
| **净变化** | **约 −3.0K 字符/轮（−4%）** |

**风险**：若把因子表塞进 4 路，每轮 +5–8K 字符（+10%），且 4 路重复。**禁止**。
**影子 A/B**：0 次额外 LLM 调用（同一快照复算），不得为影子单独跑模型。
**门槛**：E4，单轮字符数不得高于 v0.249.0。

### 6.3 信息过载

**现状**：弹窗 = 5 chips + 7 列表格（11 行）+ 左右两面板；审计 P1-2 已经证明它在 1024×768 上只剩 0px 余量（修好后刚好不裁）。

**缓解**：

1. P1 **0 新增行/列/卡片/面板**；U1 只替换文本且 `nowrap` 1 行，U2 复用第 3 格，U3 替换空态。
2. 规则：**只有参与门槛的因子才允许出现在 UI**。没有门槛的因子（MA20、RSI、量比、位置）一律不进快照、不进 UI。
3. 表格行高增量必须为 0（T10）；若文案放不下，截断 + title，不许换行撑高。
4. 因子明细（B1）只在 P2 且用 tab **替换**内容，不追加高度。

**可测门槛**：1024×768 `.tw-ad-autot-tablewrap.scrollHeight` 改动前后差值 ≤ 0；`.tw-ad-autot-body` 无滚动。

### 6.4 做T 误导

**机制**：精确到小数点的因子值 + 「通过/不足」天然像推荐；影子收益一旦可见，会被读成「另一套更赚」。

**缓解**：

1. 用词：`条件满足` / `条件不足`，**永不**用「可做」「建议」「适合」。
2. 门槛是**必要条件**：title 固定写「满足条件不等于会做；Agent 仍可能不给计划」。
3. 不评分、不排序、不给「最佳标的」。
4. 被门槛挡住不是「坏事」：`条件不足` 用 muted，不用红。
5. 影子只写「过去 N 轮 A/B 各挡了什么、实际净额是多少」，不写「B 更好」，不自动切换。
6. 计划净额必须标「计划值，未成交」。

**可测门槛**：E8 禁用词；文案评审 checklist；上线首周人工抽查 20 条反馈/截图。

### 6.5 门槛过拟合

**机制**：阈值（1.5%/3.0%/20 元）是经验值；样本一多就会有人想调。按单一样本手调 = 过拟合（R9 禁止）。

**缓解**：

1. 阈值写死在 `T_GATE` 常量，**用户不可配**；改动必须 bump `T_GATE_VERSION` + CHANGELOG。
2. 影子一次只测**一个变量**（如 ATR 1.5→2.0），不扫参数网格。
3. 读报告前样本 ≥20 个完成轮；不足只写「样本不足」。
4. 不自动晋升；任何阈值变更都要人审。
5. ATR 门槛必须 ≥ `1.2 × 最小价差`（1.5 ≥ 1.44），否则门槛自相矛盾——加一条断言。

### 6.6 静默失败与性能

**机制**：现有代码多处 `catch {}`（审计 #6/#7/#19）；因子层若复制这个习惯，会出现「看起来没计划，实际是取数失败」。

**缓解**：

1. 取数失败 = `unknown`，必须上屏（`—（日K未取到：原因）`），**不得降级成 `pass` 或 `reject`**；fail-closed：不新挂 T。
2. 日志写失败 → `run.warnings` + 状态条可见，不吞。
3. 因子快照每日只算一次，30s GET 只做内存 join；E2/E6。
4. 单日日志行数上限 3,000；超限丢最旧并计数，不无限增长（#20 的教训）。

## 7. 附录

### A. 因子定义与门槛（t-gate-v1）

| 因子/项 | 定义 | 数据 | 门槛 | 缺失/不足 |
| --- | --- | --- | --- | --- |
| `bars` | 可用日K根数（`fqt=1`，剔除当日未完成 bar） | `fetchKline(secid,101,30,1)` | ≥ 25 | `bars-short` |
| `asof` | 最后一根**已完成** bar 的日期 | 同上 | 距今天 ≤10 自然日 | `stale` |
| `atr14Pct` | ATR14 ÷ 最后收盘 ×100（复用 `atrFromBars`） | 同上 | ≥ 1.50% | `atr-low` |
| `amp20Pct` | (20日最高 − 20日最低) ÷ 最后收盘 ×100（区间振幅，不是日均振幅） | 同上 | ≥ 3.00% | `amp-low` |
| `spreadPct` | (卖价/买价 − 1)×100 | 计划 | ≥ 1.2% | `fee-net`（与净额合并展示） |
| `feeNet` | (卖−买)×股数 − 双边费用（佣金万3最低5 + 印花税卖出0.05% + 过户费；ETF 免印花） | `feesOf` | ≥ max(20 元, 0.3%×买入额) | `fee-net` |
| `roundUsed` | 当日该标的完成轮 + 未完成计划 | `prism-autot.json` | < 2 | `round-cap` |
| `deadline` | 14:50（`run.startedAt` 所在日） | run 时钟 | now < deadline | `deadline` |

> **口径硬约束**：所有因子只用**昨日收盘前**的日K。理由：盘中最后一根是未完成 bar，09:35 的 ATR 会被 5 分钟的小振幅压低，导致早盘误拒；且当日多次计算必须得到同一值（T11）。
> **单位**：A股 `vol` 单位是手（1 手=100 股），本期不使用成交量因子，避免单位坑。

### B. 门槛优先级与文案表

**优先级（从高到低，取第一条命中）**：

| 序 | code | 触发 | 文案（≤22 全角） |
| --- | --- | --- | --- |
| 1 | `off` | 该标的开关关闭 | `未开启做T` |
| 2 | `risk` | 回撤闸门触发 / 主决策同标的减仓 / 触及止损 | `风控冻结 · 回撤闸门` / `风控冻结 · 主决策减仓` / `风控冻结 · 触及止损` |
| 3 | `deadline` | now ≥ 14:50 | `已过截止 14:50` |
| 4 | `live-plan` | 有 pending/open-filled 计划 | 显示计划本身（`[正T] 1.236 ↔ 1.248`） |
| 5 | `round-cap` | `roundUsed ≥ 2` | `已达 2 轮上限` |
| 6 | `no-data` | 日K取数失败 | `—（日K未取到：<原因>）` |
| 7 | `bars-short` | `bars < 25` | `—（日K不足 N 根 < 25）` |
| 8 | `stale` | `asof` 距今 >10 天 | `—（日K停更 N 天）` |
| 9 | `atr-low` | `atr14Pct < 1.50` | `条件不足 · ATR 1.12% < 1.50%` |
| 10 | `amp-low` | `amp20Pct < 3.00` | `条件不足 · 振幅 2.41% < 3.00%` |
| 11 | `fee-net` | 计划净额不足 | `条件不足 · 净额 15.80 < 20.00` |
