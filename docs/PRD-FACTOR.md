## 0. 裁决（先给结论）

| # | 裁决 | 一句话理由 |
| --- | --- | --- |
| **D1** | **因子层只服务「自动做T 的可执行性门槛」**：不选股、不评分、不排序、不进四路分析、不进主决策下单；**因子口径不自定义**，全部引用 FACTOR-SPEC。 | 主决策已有 LLM + 行业暴露 + 回撤闸门；再加一层因子观点只会增加 token 与同质化。 |
| **D2** | **因子层不是审计修复的替代品**：44 条审计项里**直接解决 0 条**，部分改善 3 条（#13 / #24 / UI P1-5 文案），另有 1 处会加重风险（#20 文件膨胀）。**12 条宿主项仍开放**，其中 #10/#11/#16 是 P1。 | 因子层解决的是「为什么没做、门槛是否可信」；审计里绝大多数是「净持仓、账本、生命周期」——两件事。 |
| **D3** | **第一期 0 大改**：自动做T 弹窗 3 处因子文案 + 2 处既有口径纠错（N-1/N-3），不新增按钮/卡片/列/面板，按用户规则由产品经理决断，**不需要 HTML 原型**。 | 全部是替换已有文本，布局变化为 0；见 §3.3 与 §2.6。 |
| **D4** | **因子日志只落盘；影子 A/B 只落盘，达到 30 个交易日才出报告；两者永不进主界面**。 | 日志是排障资产；影子在 <30 天时只能算方向性证据，展示即误导（FACTOR-VALIDATION §6）。 |
| **D5** | **5 个 chip 的数量与标签不变，不加第 6 个**；仅修正「今日轮次」的错误分母（N-1）。 | chips 是唯一汇总口径；因子是标的级条件，不是汇总指标。加「门槛通过数」会与「今日轮次」打架（通过 ≠ 做了）。 |
| **D6** | **绝对波动阈值只当「下限」，不当「筛选器」**：实测 `ATR14≥1.5%` 通过 91%、`20日区间≥3%` 通过 95%，等于没筛；真正有**区分度**的闸放在 `ATRRANK120`（自身历史分位）与扣费净额；**是否有经济效果仍待 VALIDATION**。 | 继续拿绝对阈值当卖点，会让用户以为「条件满足」=「被选中」，是新的口径撒谎。 |
| **D7** | **P1 不宣布任何门槛「有效」**：只交付「拒绝理由可核对」。有效性要走 FACTOR-VALIDATION 的 G0–G4；当前 `results=0`，连做T净期望都没有样本。 | 把「能解释」说成「有效」是越级；先把结算与对账修好。 |

**一句话结论**：因子层值得做，但只值得做「**一条可核对的拒绝理由**」；做完之后用户应当能回答「今天这只为什么没做T、差多少」，而不是看到一张因子表。**在 #10/#11/#16/#24 关闭之前，不要对外宣称自动做T 已优化完成。**

## 1. 需求范围：哪些进 UI，哪些只做后台

### 1.1 现状与问题（为什么不是「再加一个面板」）

| 现状 | 证据（v0.249.1） | 用户后果 |
| --- | --- | --- |
| 「适不适合做T」只写在提示词里：ATR14/现价 ≥1.5%、20 日振幅 ≥3% | `prismPipeline.ts:189` | 模型可以忽略；没有代码拒绝；事后无法核对 |
| 实测这两个绝对门槛在全池几乎不筛：`ATR14≥1.5%` 过 **91%**（51/56）、`20日区间≥3%` 过 **95%**（53/56）；ATR 中位 **4.95%**、区间中位 **27.92%** | `FACTOR-SPEC.md` §0.1（本机 56 只，as-of 2026-11-26） | 就算把规则写进代码，也只会得到「几乎全部通过」；用户仍看不出「为什么没做」 |
| ATR14 / 20 日振幅已算好并喂给模型 | `prismRoutes.ts:365-389` | 数有了，但**没有判定、没有留痕、界面看不到** |
| 引擎真正的硬门槛散落在多处：轮次上限、20% 底仓、1.2% 价差、20 元净额 | `prismRoutes.ts:678/681/683/688` | 被拒时 `continue` 静默跳过：不写计划、不写原因、UI 无痕 |
| UI 对「没有计划」给的是猜测式并列原因 | `prismDeskSide.ts:609-618`：`今日无计划` + title「价差不足/风控/数据缺失」 | 用户不知道到底是哪一条；这是「三选一猜谜」，不是解释 |
| 毛价差与净额不同口径 | `prismDeskSide.ts:636-640` 只算 `sell/buy−1`；计划卡写「价差（扣费前）」 | 看到 +1.83% 以为赚，实际扣费后可能只剩 83 元甚至被拒 |
| **实测 `plans 25 / trades 24 / results 0`，25 条计划全部 `aborted`；24 条成交是 12 个计划的单腿分批** | `FACTOR-SPEC.md` C6、`FACTOR-VALIDATION.md` §0 | 现在没有「完成轮」样本；此时谈胜率/收益都是空的，先把结算与对账修好 |

结论：**因子层的第一价值是「把已经存在的判定变成可见、可核对、可留痕的事实」，不是新增因子。**

### 1.2 四个能力的产品定义

| 能力 | 定义（产品口径） | 不是什么 |
| --- | --- | --- |
| **因子快照** | 每标的每日一份、**只用到昨日收盘为止的日K**（剔除当日未完成 bar）的 5 个值：`ATR14%`、`ATRRANK120`、`AMP20`（日均振幅）、`TICK`（一跳占比），加 `bars` / `asof` / `gateVersion`；计划级另有 `netEdge%`。 | 不是盘中实时因子；不是 12+17 的全量因子库；不含 MA/RSI/量比/位置等未设门槛的指标。 |
| **确定性门槛** | 引擎在挂单前按 FACTOR-SPEC §4.2 的门槛链判定「能不能做」，产出**唯一的第一阻断原因**；门槛是必要条件，不是充分条件。 | 不是评分、不是排序、不是买卖信号；不改 LLM 的选价/选方向。 |
| **因子日志** | 每次研判对每只开启做T 的持仓写一行：因子值 + 门槛版本 + 判定 + 影子判定。日分片、30 天保留。 | 不是用户可见报表；不是第二套账本；不参与成交与结算。 |
| **影子 A/B** | 同一份快照上，用 B 门槛（**单一变量**）再判一次，只记录「B 会不会挡」，**不挂单、不调用 LLM**；30 个交易日后才出描述性报告。 | 不是模拟交易；不是收益预测；不自动切换门槛。 |

### 1.4 只做后台、不展示的

| 能力 | 落点 | 为什么不展示 |
| --- | --- | --- |
| 完整因子快照（逐标的 JSON） | `prism-factor/<day>.jsonl` | 5 个值 + 元数据已足够解释；全量展示会诱发「自己看因子择时」 |
| 因子日志（逐轮逐标的） | 同上，30 天保留 | 日频看无价值；只在排障/复盘时读 |
| 影子 A/B 判定与报告 | 日志字段 + `scripts/verify-prism.mjs --factors` 输出 | 30 天前展示即误导；达标后也只写「过去 N 轮发生了什么」 |
| 门槛版本变更记录 | `T_GATE_VERSION` 常量 + CHANGELOG | 版本进 title 即可，不需要界面 |
| 被拒计划的原始买/卖价 | 日志 `kind:"plan"` 行 | 展示会变成「马后炮价格」，诱导「要是当时挂了就赚了」 |

### 1.5 明确不做的（本期与可见未来）

| 不做 | 理由 |
| --- | --- |
| 第 6 个 chip「今日可做 N 只」 | 通过 ≠ 做了；与「今日轮次」语义打架；`<560` 的 2 列 chip 布局会变形 |
| 决策流「做T」tab 增加「未通过门槛」分组 | 未通过门槛不是委托，混进委托流会伪造「有一笔单被拒」的观感；弹窗已能回答 |
| 因子评分 / 星级 / 置信度 / 候选排名 | 与 R10 冲突（不得表述为有预测能力）；ATR 分位只做二元闸，不做名次 |
| 因子进四路分析或主决策 | 见 D1；v0.249.1 刚把重复注入修掉，不能加回去 |
| 用户可调门槛（settings） | 没有样本就调参 = 过拟合；且需要新设置 UI（大改） |
| 因子回测引擎 / 机器学习 | 免费源无历史分单/逐笔，回测口径不可信；本期只做「同日同快照的影子对照」 |
| 12 核心 + 17 扩展的全量因子页 | 单标的做T 只需要 5 个门槛因子；全量是定义库存，不是上线清单（FACTOR-SPEC §0.3） |

## 6. 风险

### 6.1 四角色同质化（主通道已修，仍需守门）

**机制**：v0.249.1 之前，`inputs.autoT` 在 `compileInput` 里，4 路分析各一份；汇总又重复拼一次 ⇒ 一轮 6 份。因子层再加数值，会让四路引用同一组数字，输出趋同。

**已做**：v0.249.1（`d27fba9`）从 `compileInput` 移除 autoT，只在汇总 prompt 拼接一次。

**剩余风险**：后续为「让分析更懂做T」把因子加回四路；或新增「量化因子」角色。

**缓解（P1 必做）**：

1. 因子值只进**汇总/决策**调用，不进 4 路分析。
2. 不新增「量化因子分析」角色。
3. 提示词明确：`不要在四路分析里复述 ATR/分位/日均振幅`。
4. E3 回归断言：4 路 `compileInput` 不含 `【自动做T`。

**可测门槛**：E3；上线后抽查 4 路文本，`ATR`/`ATR分位`/`日均振幅` 出现次数 = 0。

### 6.2 token 成本

**基线**：单轮约 78K 字符（≈45–55K token，AUDIT-PRISM-PROMPT P2-1）。v0.249.1 已把 autoT 段从 6 份降到 1 份，单轮约 **−3.5K 字符**。

**因子层的账（在 v0.249.1 基础上）**：

| 项 | 变化 |
| --- | --- |
| autoT 上下文由 2 个值扩到 5 个值（通过门槛的标的才进，通常 ≤4 只） | +0.3K 字符 |
| 提示词删掉 ATR1.5%/区间3% 规则，改为一句「引擎已过滤 + s=ATR/4」 | −0.2K |
| 新增门槛结论行（汇总） | +0.1K |
| **净变化** | **约 +0.2K 字符/轮（+0.25%）** |

**风险**：若把 5 个因子塞进 4 路，每轮 +3–5K 字符（+5%），且 4 路重复。**禁止**。
**影子 A/B**：0 次额外 LLM 调用（同一快照复算），不得为影子单独跑模型。
**门槛**：E4，单轮字符数不得高于 v0.249.1 + 2%。

### 6.3 信息过载

**现状**：弹窗 = 5 chips + 7 列表格（11 行）+ 左右两面板；审计 P1-2 已经证明它在 1024×768 上只剩 0px 余量（修好后刚好不裁）。

**缓解**：

1. P1 **0 新增行/列/卡片/面板**；U1 只替换文本且 `nowrap` 1 行，U2 复用第 3 格，U3 替换空态。
2. 规则：**只有参与门槛的因子才允许出现在 UI**。EFF20/FILL/LIMITDIST/VWAP 等未进 P1 门槛的因子，一律不进快照、不进 UI。
3. 表格行高增量必须为 0（T10）；若文案放不下，截断 + title，不许换行撑高。
4. 因子明细（B1）只在 P2 且用 tab **替换**内容，不追加高度。

**可测门槛**：1024×768 `.tw-ad-autot-tablewrap.scrollHeight` 改动前后差值 ≤ 0；`.tw-ad-autot-body` 无滚动。

### 6.4 做T 误导

**机制**：精确到小数点的因子值 +「通过/不足」天然像推荐；影子收益一旦可见，会被读成「另一套更赚」。

**缓解**：

1. 用词：`条件满足` / `条件不足`，**永不**用「可做」「建议」「适合」。
2. 门槛是**必要条件**：title 固定写「满足条件不等于会做；Agent 仍可能不给计划」。
3. 不评分、不排序、不给「最佳标的」；ATR 分位只做自身历史分位，不做候选名次。
4. 被门槛挡住不是「坏事」：`条件不足` 用 muted，不用红。
5. 影子只写「过去 N 轮 A/B 各挡了什么、实际净额是多少」，不写「B 更好」，不自动切换。
6. 计划净额必须标「计划值，未成交」。

**可测门槛**：E8 禁用词；文案评审 checklist；上线首周人工抽查 20 条反馈/截图。

### 6.5 门槛过拟合与「假筛选力」

**机制**：绝对阈值（ATR 1.5% / 区间 3%）在本池通过 91%/95%，**本身没有筛选力**；若把它当卖点，用户会以为「条件满足 = 被选中」。真正有**区分度**的是 `ATRRANK120`（自身历史分位）与扣费净额，但「有区分度」不等于「有经济效果」，且分位窗口/阈值同样可能过拟合。

**缓解**：

1. 绝对阈值只当**下限**，对外文案不写「筛选」；P1 的筛选结论必须来自 G3/G9。
2. 阈值写死在 `T_GATE` 常量，**用户不可配**；改动必须 bump `T_GATE_VERSION` + CHANGELOG。
3. 影子一次只测**一个变量**（首个变量：`ATRRANK120 ≥ 50`，不是绝对 ATR），不扫参数网格。
4. 读报告前样本按 FACTOR-VALIDATION：影子 30 个交易日；<20 天写「样本不足」，20–29 天只写「方向性证据」。
5. 不自动晋升；任何阈值变更都要人审。
6. 断言：`ATR 下限 ≥ max(1.0, 2×(feeRT+2×TICK))`；`AMP 下限 ≥ max(1.2, 0.6×ATR14)`；两者不得低于成本线。
7. **P1 不宣布任何门槛「有效」**；有效性走 FACTOR-VALIDATION 的 G0–G4。

### 6.6 静默失败与性能

**机制**：现有代码多处 `catch {}`（审计 #6/#7/#19）；因子层若复制这个习惯，会出现「看起来没计划，实际是取数失败」。

**缓解**：

1. 取数失败 = `unknown`，必须上屏（`—（日K未取到：原因）` / `—（行情过期 42s）`），**不得降级成 `pass` 或 `reject`**；fail-closed：不新挂 T。
2. 日志写失败 → `run.warnings` + 状态条可见，不吞。
3. 因子快照每日只算一次，30s GET 只做内存 join；E2/E6。
4. 单日日志行数上限 3,000；超限丢最旧并计数，不无限增长（#20 的教训）。

其中 `s = ATR14%/4`；`2s = 目标毛捕获`；`feeRT% = 双边费用 / N × 100`；`minSpread% = max(0.8, 2.2×feeRT + TICK, 0.25×ATR14)`。

> **两处废止（与 FACTOR-SPEC 对齐）**：
> ① 旧 `amp20Pct = (20日最高−20日最低)/收盘` 是**区间幅度**，不是日均振幅；本期改用 `AMP20`（日均），区间另名 `RANGE20` 且不进本期门槛。
> ② 旧固定 `1.2%` 最小价差废止，改用上面的 `minSpread%` 公式；`20 元` 绝对净额下限由 `netEdge ≥ 0.25%` + `N ≥ 5000` 取代（更可复算）。若实现保留 `20 元` 作为额外下限，必须同时满足 `netEdge ≥ 0.25%`，且 UI 只展示一套口径。
