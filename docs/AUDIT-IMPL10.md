## 第 1 段：批量粘贴录入（P2-9）

- **入口**：放进持仓页分组「…」菜单（`{ label: '批量录入' }`），**没有新增常驻按钮**（开发原则 1）。
- **三步模态** `src/client/BulkPaste.tsx`：`① 粘贴 → ② 预览 → ③ 完成`，标题右侧显示当前步。
  - 文本框 + 落点分组下拉（默认当前分组，取 `archive` 之外的分组）；摘要一行（`可写入 N 条 · 建仓 a · 买入 b · 卖出 c · 报错 d 行`）。
  - 预览表列：行 / 代码 / 名称 / 日期 / 数量 / 价格 / **记为**（`建仓（买入）` / `买入` / `卖出`）。
  - **解析失败逐行报错并保留原文**（`第 N 行：<原因>` + `<code>原文</code>`），原文可复制回去改。
  - 写入：`api.mutatePortfolio`（`addPos` → `buy`/`sell`）—— **只走既有账本写入路径，不自己写文件**。
  - **一次撤销**：每条写入的 note 带批次标记 `批量录入#<id>`，撤销调宿主 `deleteLedger` 按前缀反删；
    宿主侧把删掉的原件摘要写成一条 `pnote`（**留痕**，可追溯）。
  - **键盘**：`role=dialog` + `aria-modal` + `aria-label`；打开即聚焦首个控件；`Tab` 在模态内循环（首尾相接、焦点被拖出也拉回）；
    `Esc` 关闭（`Modal` 之外由宿主 `tw-mask` 的 Esc 处理）；关闭后由界面把焦点还原到「…」菜单触发器。
- **解析层** `src/client/bulkPaste.ts`（纯函数，7 条断言）：五种分隔符（`|`/`｜`/Tab/`,`/`，`）、列数不足/过多、
  空行跳过、完全重复行、非数字、两种日期格式（`YYYY-MM-DD` 与 `YYYY/MM/DD`，单位数归一）、
  **与逐条手工录入字段级等价**（`{secid,name,qty,price,ts,note}` 逐字段 deepEqual；`ts` = 当日 15:00）。
  另外两条产品判断：**卖出但本地无持仓 ⇒ 直接报错**（托管侧必然失败，提前说清楚）；连续分隔符**不合并空列**（合并会让列错位）。

### 实测：批量写入 → 撤销的往返一致（真实宿主，临时目录）
```
写入前（分组+持仓 2 条本地记录）： { buy: 0, sell: 0, pnote: 0, total: 2 }
写入 3 条（两买一卖，卖出放次日以符合 T+1）： { buy: 2, sell: 1, pnote: 0, total: 5 }
撤销（deleteLedger notePrefix=批量录入#test）： { buy: 0, sell: 0, pnote: 1, total: 3 }
落盘后新实例再读： buy = 0（交易条数确实还原）
留痕： 撤销批量录入：反删 3 条交易流水（Emv3a4qbg00053uxy、Emv3a4qbi0006knsa、Emv3a4qce0007hcpu）
```
即：交易流水**精确还原**，额外留一条 `pnote` 作为撤销痕迹（这是"留痕"要求本身，不是残留）。

### D1（P1）`deleteLedger` 从"子串"改成"整词精确匹配"

- 契约写死：批次标记 = `批量录入#` + 1–12 位 base36（客户端写**定长 8 位**），判定规则见 `shared/model.ts` 的
  `BULK_BATCH_RE` / `bulkBatchesOf` / `bulkBatchMatches`：**标记前必须是串首或空白**、**标记后必须不是词字符**。
  字段也从 `notePrefix` 改成 `noteMarker` —— 名字叫"前缀"而实现按前缀匹配，正是这次误删的病根。
- **取舍写死并钉进断言**：`批量录入#1x` **不**被 `批量录入#1` 命中（`x` 是词字符），`批量录入#12` 同理；
  `卖 批量录入#1`（方向词在前）**要**被命中（客户端就是这么写的）。
- 最小复现跑前/跑后：
```
删除前 批量相关 note = ["批量录入#1","批量录入#12","批量录入#1x","x批量录入#1"]
删除后 存活的批量 note = ["批量录入#12","批量录入#1x","x批量录入#1"]      ← 只删了 #1 ✓
```
- **修前会失败的证据**（把 `bulkBatchMatches` 临时换回 `note.includes`）：
